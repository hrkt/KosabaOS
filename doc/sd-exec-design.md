# SD からの exec の設計

状態: 設計 (2026-11-08、branch `sd-exec`)。対象は SYS_EXEC
(8) で `/sd` 上の ELF を実行できるようにすること。
新しい syscall は足さない。読み取り側の設計は
doc/sd-design.md、書き込み側は doc/sd-write-design.md。

## 背景

- 現状、exec は RAM FS 上の ELF だけが対象で、/sd 配下の
  パスは do_exec が -1 で断っている (sd-design.md の
  「v1 の対象外」)。ただし部品は揃っている: FAT の検索と
  位置指定読み (fat_find / fat_read_at)、cwd を含むパス
  解決と正規化 (FS 段4)、ページ単位の ELF ロード
  (exec 多段化)。
- 実需: SD に置いたプログラムをそのまま走らせること
  (単独コンピュータ軸の一歩)。IwaC の生成物や Ikesu の
  成果物を、カード経由で実機に持ち込む道にもなる。

## 決め事

1. **パス判定**: resolve_path で正規化した絶対パスが /sd
   配下 (is_sd_abs) なら FAT から、それ以外は RAM FS から
   読む。cwd が /sd の中にある場合の相対名も、解決後は
   絶対パスになるので同じ経路に乗る。分岐は trap.c の
   do_exec (と、ローダを共有する do_job_run) だけに置く。
2. **ローダ**: elf.c の読み出しを「位置指定読みの関数
   ポインタ + ファイル文脈」に一般化する。fs_read_at と
   fat_read_at はどちらも (file, pos, dst, n) の同型
   なので、読み口を差し替えるだけで両対応になる。
   elf_load_to (fs_file 版) は互換の橋渡しとして残し、
   カーネル起動時の Nish 起動など既存の呼び出しは
   無変更にする。ページ確保・領域の範囲チェック・
   失敗時の巻き戻し (vm_pages_release) は既存の経路
   そのまま。サイズ上限も既存の VA 領域の制限そのまま。
3. **読みの性質**: FAT の読みは fat_read_at (鎖をたどる
   位置指定読み) で賄う。ローダはヘッダ→プログラム
   ヘッダ→セグメントの順に前から読むので、鎖たどりと
   相性がよい。読み途中でカード側のエラーが起きたら
   fat_read_at は「読めた分だけ」を返し、ローダの
   truncated 系の失敗として既存の -1 経路に落ちる。
4. **書き込み中のファイルは実行しない**: create したまま
   close していない SD ファイルを exec しようとしたら
   -1。理由は、目録項のサイズと開始クラスタは close
   (fat_close_write) で初めて書き戻されるためで、書き
   込み中のファイルは目録上は「サイズ 0、または切り捨て
   前の古い姿」に見え、読んでも正しい ELF にならない。
   「書いてすぐ実行」は close を挟めば済むので、この
   単純な形で困らない。点検は unlink の「開いている
   ファイルは消せない」と同じ流儀で、目録項の位置
   (dir_cluster / dir_off) を全段・全ジョブの fd テーブル
   と照合し、writable な開き方があれば弾く。読み用に
   開いているだけなら内容は目録どおり確定しているので
   問題ない。RAM FS 側にこの問題が無いのは、fs のサイズ
   が書き込みのたびに育つためで、従来どおりとする。
5. **ジョブ (job_run = 20)**: do_exec とローダ・引数の
   処理を共有しているので、SD 対応はそのまま効く。
   syscalls.md の job_run の「失敗は exec と同じ理由で
   -1」という記述とも揃う。
6. **テストで ELF を SD に載せる方法** (論点だったもの):
   Nish の write はテキスト前提で、バイナリをそのまま
   書く用途には使えない。環境ごとに分ける:
   - virt: make_sd_image.py にホストファイルを取り込む口
     (追加引数 `名前=ホストパス` でルートに置く) を足し、
     build.sh が user.elf を UPROG.ELF としてイメージに
     埋める。シナリオは `run /sd/UPROG.ELF` の挨拶と
     終了ステータス (シナリオ K の SD 版) に、cwd を
     /sd に移しての相対名実行を加える。
   - 実機: RAM FS 上の ELF を /sd へコピーする小さな
     ユーザープログラム copy.elf を用意する (open / read /
     create / write / close の既存 syscall だけで書ける)。
     実機シナリオは「コピー → /sd の ELF を run」の往復。

## 割り切り

- 実行中の ELF ファイル自体を unlink や上書きから守る
  仕組みは足さない。ロードは起動時に全部読み切るので、
  実行後に元ファイルが変わっても影響しない (RAM FS 側
  も同じ扱い)。
- SD から読む分だけ起動が遅くなるのは許容する。
  同時実行のモデル (exec 多段・ジョブ) は従来どおり。
