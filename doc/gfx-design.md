# 画面表示の設計（描画 syscall と窓）

状態: 設計（2026-11-07 作成）。この文書で仕様を確定させてから実装する。
位置づけ: doc/future-notes.md の将来アイデア案1「画面を
ユーザープログラムに開く」。ジョブ制御（doc/jobs-design.md）まで
来て、並行で走るジョブが「見えない」ことが次の壁になった。
描画 syscall で画面をユーザープログラムに開き（段A）、走者
ごとに窓を持たせてコンソールの仲裁を窓のフォーカスとして
見える化する（段B）。

## 背景

- LCD は今はカーネルだけのもの: 起動画面（kernel.c）と
  時計タスク（proc.c の clock task が lcd_tick_draw）だけが
  描く。ユーザープログラムから画面に触る口は無い。
- 土台は boards/k210/lcd.c にある（init / fill_rect /
  draw_text（scale 付き）/ draw_u32 / tick 描画。経緯は
  doc/k210-lcd-driver.md、仕組みは doc/lcd-basics.md）。
- ジョブ制御で「走者（runner）」と「コンソールの持ち主
  （console owner）」ができた。窓はこの 2 つにそのまま
  対応させる: 窓の持ち主は走者、フォーカスは持ち主。

## 画面の分け方（時計との共存）

論理画面は 320x240（ボード層の LCD_WIDTH / LCD_HEIGHT が
正本。LCD の無い環境でも同じ値を返し、プログラムから
見た geometry は環境で変えない）。

- **時計帯: y = 216〜239** は今までどおり時計タスクの領分。
  lcd_tick_setup が (118, 216) に置く表示で、描画 syscall
  からは一切触らない。時計が消えるのは後退なので、窓系は
  この帯を避けて設計する。
- **クライアント領域: y = 0〜215**（320x216）を窓で分ける。
  起動画面の絵はこの領域に残るが、窓の枠が開くたびに
  上から描かれていく（プログラムが消せば消える。当たり前
  の割り切り）。

## 窓のモデル（段B）

窓は走者ごとに 1 つ。geometry は走者番号から決まる固定
レイアウト（動的な移動・リサイズはしない）:

| 走者 | 窓の矩形 (x, y, w, h) | 備考 |
|---|---|---|
| 0（前面） | (0, 0, 320, 216) | クライアント領域全体 |
| ジョブ 1 | (0, 0, 160, 108) | 2x2 グリッドの左上 |
| ジョブ 2 | (160, 0, 160, 108) | 右上 |
| ジョブ 3 | (0, 108, 160, 108) | 左下 |
| ジョブ 4 | (160, 108, 160, 108) | 右下 |

- 窓の矩形には枠（1px）と上部のタイトルバー（13px）を
  含む。プログラムが描ける内容領域は、窓の矩形から
  枠とタイトルバーを除いた内側: 原点 (x+1, y+13)、
  大きさ (w-2, h-14)。前面なら 318x202、ジョブなら
  158x94。
- タイトルは、ジョブは起動時のプログラム名。前面は
  exec したプログラム名（初期値は "FG"。exec のたびに
  更新し、戻っても戻さない。割り切り）。
- **フォーカス = コンソールの持ち主**。持ち主の窓は枠と
  タイトルバーを明るく（白枠＋濃い背景に白文字ではない
  強調色）、それ以外は灰色で描く。終わったジョブの窓は
  さらに暗くし、回収（fg / 次のプロンプトでの自動回収 /
  スロット再利用）で枠ごと消してデスクトップ色に戻す。
- ジョブが始まったら、カーネルが内容領域をデスクトップ
  色（起動画面の背景と同じ RGB(24,24,24)）で消してから
  枠を描く（前のジョブの残像を残さない）。
- Nish 自身は gfx を呼ばない。走者 0 の窓は「前面で走る
  プログラム」の表示面で、シェルの本拠は従来どおり
  シリアル（割り切り）。

## syscall（43〜47 を取る）

番号方針（doc/syscalls.md）に従い、デバイスの 40〜49
ブロックの空き 43 から取る。実装に先立って syscalls.md
へ追記する。引数は a0〜a2 の 3 つまでという既存の約束に
合わせ、座標の組は 16 ビットずつ詰める（x | y<<16 の形。
値は符号なしで、負座標は扱わない）。色は RGB565 の生値。

| 番号 | 名前 | 引数 | 戻り値 | 意味 |
|---|---|---|---|---|
| 43 | gfx_info | a0 = バッファ (16 バイト) | 0 / -1 | 論理画面の幅・高さと、自分の窓の内容領域の幅・高さを u32 x4 で書く |
| 44 | gfx_clear | a0 = 色 | 0 | 自分の窓の内容領域を 1 色で消す |
| 45 | gfx_rect | a0 = x \| (y<<16)、a1 = w \| (h<<16)、a2 = 色 | 0 | 窓の中の相対座標で矩形を塗る。はみ出しは内容領域でクリップ（空なら何もしない、戻り値は 0） |
| 46 | gfx_text | a0 = x \| (y<<16)、a1 = 文字列、a2 = 色 \| (scale<<16) | 0 / -1 | 文字列を描く（5x7 フォント、lcd と同じ字形）。scale は 1〜4 に丸める。文字列はカーネルに写してから描く（最大 48 文字）。ポインタが範囲外なら -1 |
| 47 | gfx_line | a0 = x0 \| (y0<<16)、a1 = x1 \| (y1<<16)、a2 = 色 | 0 | 1px の直線（Bresenham）。両端とも内容領域でクリップ |

- 点は gfx_rect の 1x1 で代用する（専用の番号は取らない）。
- 呼べるのはどの走者・どの exec の段からでもよい。描画先
  は常に「呼び出し元の走者」の窓（走者 0 の exec 鎖は
  1 つの窓を共有する）。
- ユーザーポインタの検証は既存の流儀（copy_user_string /
  copy_to_user、範囲外は -1）。数値の引数は検証せず
  クリップで吸収する（オーディオダミーがレートを検証
  しないのと同じ温度感）。

## LCD の無い環境（virt）と klog の要約

オーディオダミーと同じ流儀で、描画の検証は dmesg 経由に
する。gfx の呼び出しと窓の出来事は、両環境とも klog に
ログ専用の要約行を 1 行ずつ残す（コンソールには出さない）:

```
gfx: open r=1 "slow.elf"
gfx: focus r=1
gfx: clear r=1 color=0x001f
gfx: rect r=1 x=2 y=3 w=40 h=10 color=0xf800
gfx: text r=0 x=0 y=0 "GDEMO" scale=2 color=0xffff
gfx: line r=0 x0=0 y0=0 x1=50 y1=20 color=0x07e0
gfx: done r=1
gfx: close r=1
```

- virt では要約だけが残り、実描画は無い（gfx_info は
  上記の固定 geometry を返すので、プログラムの振る舞いは
  実機と同じになる）。
- k210 では要約に加えて実描画する。ピクセルで見える
  ところ（窓の見た目、フォーカスの移り変わり）はシリアル
  から確認できないので、目視の担当として残す。
- 描画回数の多いプログラムでは klog（16KB のリング）が
  gfx の行で回る。割り切りとして受け入れ、デモの描画
  回数は控えめにする。

## 実装の置き場所

- 共通: `gfx.c` / `gfx.h`（窓の表、geometry、クリップ、
  syscall の実体、klog 要約）。syscall の振り分けは
  trap.c の do_syscall に 43〜47 を足す。
- ボード層: LCD のある環境では boards/k210/lcd.c の
  既存部品を使う。文字のクリップ描画だけ lcd 側に
  `lcd_draw_text_clip` を足す（字形表は lcd.c の持ち物
  なので、クリップもそこで閉じる）。LCD の無い環境では
  BOARD_FEATURE_LCD で分岐し、実描画を省く。
- trap.c からの出来事の通知: job_run の成功で
  `gfx_window_open`、job の done で `gfx_window_done`、
  回収と kill_all で `gfx_window_close`、コンソールの
  持ち主の変更点で `gfx_set_focus`。前面のタイトルは
  do_exec の成功時に更新する。
- 描画は syscall の処理の中（トラップ文脈）でだけ起きる。
  走者の切り替えはトラップの区切りでしか起きないので、
  1 つの描画原語の途中では混ざらない。時計タスクの描画
  は時計帯だけで、領域が重ならない。

## 実装の段

- 段A: syscall 43〜47 の実体（窓 geometry とクリップを
  含む。枠はまだ描かない）と、描画デモ gdemo.elf。
  test.sh にシナリオ Y（fg で描いて dmesg の要約で照合）。
- 段B: 枠・タイトル・フォーカスの描画と、ジョブの窓の
  生滅の通知配線。bg デモ gjob.elf（自分の窓に周期的に
  描く）。test.sh にシナリオ Z、test-k210.py に K18
  （シリアルで追える要約と出来事まで）。

## 割り切り

- 窓の移動・リサイズ・重なりは無い（固定グリッド）。
  重ならないので z-order も無い。
- フレームバッファは持たない（ST7789 は書き専用）。
  フォーカスの描き直しは枠とタイトルバーだけに限り、
  内容領域には触らない（だから消えない）。
- 負座標、内容領域をまたぐ文字列の折り返し、scale の
  範囲外は、丸めるかクリップで捨てる。
- 前面タイトルは exec のたびの更新で、親に戻っても
  子の名前が残ることがある。
- 同時に「表に出ている」窓の扱いは 1 ハート前提
  （SMP は対象外、従来どおり）。
