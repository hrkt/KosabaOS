# ジョブ制御の設計（スケジューラ段3: bg ジョブの並行実行）

状態: 設計（2026-11-07 作成）。この文書で仕様を確定させてから実装する。
位置づけ: doc/scheduler-plan.md の段3「ユーザープログラムの常駐」。
計画では「実需が出たら」とされていたが、到達点をユーザーが
「Nish で bg ジョブにしたプログラムが並行で走ること」と命名した
ので、これが段3 の実需であり、この文書がその設計になる。

## 背景

- exec は「親が凍結し、子が走って、終わると親が戻る」モデル
  （exec 多段化、doc/exec-multilevel.md）。ページ表に出ている
  ユーザープログラムは常に最上段の 1 つだけ。
- 段1 の sleep と段2 の常駐タスクで、カーネル側には「寝て起きる」
  「常駐する」形ができた。段3 はそれをユーザープログラムへ広げる。
- 原則は計画どおり: 新スケジューラは作らず既存の仕組みを育てる、
  優先度は入れない。

## 表面（Nish のコマンド）

- `run <プログラム> [引数...] &` — 末尾の `&` でバックグラウンド
  起動。起動できたら `job N: <名前> started` と出す（N は
  ジョブ番号）。プロンプトはすぐ戻る。
- `jobs` — 内部コマンド。ジョブの一覧と状態を 1 行 1 件で出す。
  無ければ `no jobs`。
- `fg [N]` — ジョブを前面にして、終わるまで待つ。N を省略したら
  「一番大きい番号の、終わっていないジョブ」。結果の出し方は
  run に倣う（0 なら無言、-2 なら `fg: program faulted`、
  それ以外は `fg: exit status N`）。
- Done 通知 — プロンプトを出す前に、終わったジョブがいれば
  `job N: <名前> done status=S` と 1 回だけ知らせる（Linux の
  Done 通知の縮小形）。通知したジョブは、その次のプロンプトの
  ときに自動で回収する（fg すればその場で回収し、ステータスが
  fg の戻り値になる）。

ジョブの状態表示（jobs と Done 通知で共通の文面、カーネルが作る）:

```
job 1: slow.elf running
job 2: uprog.elf stopped
job 3: crash.elf done status=-2
```

## syscall（20〜22 を取る）

番号方針（doc/syscalls.md）に従い、「プロセスとメモリ」の
20〜29 ブロックから 3 つ取る。実装に先立って syscalls.md へ
追記する。

| 番号 | 名前 | 引数 | 戻り値 | 意味 |
|---|---|---|---|---|
| 20 | job_run | a0 = パス、a1 = 引数文字列 | ジョブ番号 (1〜) / -1 | プログラムを bg ジョブとして起動する。入口の約束（a0 = argc、a1 = argv）は exec と同じ |
| 21 | job_list | a0 = バッファ、a1 = 大きさ | 書いたバイト数 / -1 | ジョブの一覧をテキストで書く（tasks (11) と同じ流儀）。空なら 0 バイト |
| 22 | job_wait | a0 = ジョブ番号 | 終了ステータス / -1 | 対象が終わっていれば即座にステータスを返して回収。実行中なら、そのジョブをコンソールの持ち主にして終わるまで待ち、ステータスを返して回収。フォルトは -2 |

- 呼べるのは根のプログラム（exec の段 0 で動いているもの =
  実際には Nish）だけ。それ以外からの呼び出しは -1。
- job_run の失敗は exec と同じ理由で -1（ファイルが無い、
  ELF でない、プール枯渇、ジョブが満杯）。

## コンソール仲裁（Linux の縮小形、ユーザーと合意済み）

コンソール（シリアル 1 本）の持ち主は常に 1 つだけ:

- 既定の持ち主は前面の流れ（根のプログラムと、その exec の段）。
- job_wait で待っている間は、そのジョブが持ち主になる。
- getc（2）は持ち主にだけ文字を配る。bg ジョブが getc を呼んだら、
  そのジョブは「入力待ちで停止 (stopped)」になる。ジョブの文脈は
  ecall の位置で保存され、持ち主になって再開されたときに getc が
  やり直される（文字はそのときに初めて配られる）。
- putc（1）は誰でもいつでも出してよい。bg の出力は前面の出力に
  混ざる（止めない、行単位の調停もしない）。

持ち主が getc で文字を待つ間は、カーネル内でポーリングしながら
実行可能なジョブに番を回す（ジョブが無ければ従来どおりの待ち）。
ジョブの実行中に打たれた文字は UART の FIFO に残る分だけ
保持される（virt の 16550 で 16 バイト）。溢れた分は失われる。

## 実行モデル

### 走者（runner）という考え方

trap.c の中に「今 CPU を使っているユーザープログラムの流れ」を
表す走者を置く:

- 前面の走者 1 つ: 根のプログラムと exec の段の流れ（従来の姿）。
- ジョブの走者 最大 JOB_MAX 本（下記の上限）。

各ジョブは専用に持つ:

- ページ台帳 1 段（vm.c の台帳を、exec 用の段の後ろに JOB_MAX 段
  ぶん足す。物理ページは従来どおりプールから実需で借りる）
- fd テーブル 1 つ（exec の段ごとのテーブルと同じ並びに足す）
- cwd 1 つ（起動時の前面の cwd を引き継ぐ）
- 保存済みの文脈（レジスタ 32 個 + sepc + ユーザー sp）

前面の走者にも、ジョブへ番を渡すときのための文脈の保存場所を
1 組持つ。exec_depth（段の深さ）は前面の走者の中だけの話で、
ジョブが走っている間は値が残っているだけで、ジョブ側の syscall は
それを参照しない（振り分けは走者で行う）。

### 切り替えの場所

切り替えはトラップの区切りでだけ起きる。カーネルの中で
任意の場所から飛び移ることはしない:

1. タイマ割り込み（ユーザーモードから）: ラウンドロビン。
   実行可能な走者が他にいれば、次の走者へ（量子は割り込み間隔
   = 100ms）。
2. getc: 持ち主で文字が無く、実行可能なジョブがいればジョブへ
   （自分の文脈は ecall の位置で保存。戻ってきたら getc を
   再実行する）。bg ジョブの getc は、上記のとおり停止して
   持ち主（または次の実行可能な走者）へ。
3. ジョブの exit / フォルト: そのジョブを done にし、待っている
   前面（job_wait）がいればステータスを渡して前面を起こす。
   いなければ次の実行可能な走者へ。
4. job_wait: 呼び出し側（前面）は待ち状態になり、対象のジョブ
   （と他の実行可能なジョブ）に番が回る。

切り替えのときは、相手の台帳を vm_apply_pages でページ表へ
反映し、fd テーブルと cwd を相手のものに差し替える
（exec 多段化の resume_parent がやっていることの一般化）。

### 障害の分離

ジョブがフォルトしたら、そのジョブだけが done (status = -2) に
なる。ページはプールへ返し、fd は締める（SD 書き込みの締めも
含む）。前面と他のジョブの台帳・fd・cwd には触らない。
Nish が巻き込まれないことが到達点の一部である。

## 上限と割り切り

- JOB_MAX = 4。ジョブ番号はスロット番号（1〜4）で、空いたら
  再利用する。満杯のときの job_run は -1。
- bg ジョブからの exec は -1（入れ子は作らない）。ジョブ管理の
  syscall (20〜22) も、ジョブの中からは使えない。
- kill は無い。止める手段は、fg にしてプログラム自身の流儀で
  終わらせるか、シェルを exit すること。根のプログラムが exit /
  フォルトしたら、全ジョブを終了させてページを返す
  （ジョブはシェルのセッションと運命を共にする）。
- fg の割り込み（Ctrl-C で前面ジョブをやめる等）は無い。
  fg 中のジョブが入力を待てば、そのまま入力が届くまで待つ
  （持ち主なので文字は届く）。
- ファイルの競合: 開いているファイルを unlink できない規則は、
  全走者の fd テーブルを見て判定する（従来は exec の段だけ
  だった）。それ以外の同時アクセスの調停はしない
  （同じファイルへの同時書き込みなどは未定義でよい）。
- オーディオ (40〜42) の状態は従来どおり全体で 1 つ。
  ジョブごとにはしない。
- 同時に「表に出ている」ページテーブルは従来どおり 1 走者の分
  だけ（切り替えのたびに書き換える）。SMP は対象外。

## テストの物差し（test.sh）

新シナリオで次を順に見る（W は段2 の時計シナリオが使うので、
ジョブ制御は X とする）:

1. `run slow.elf 8 &` でプロンプトが即戻り、ジョブの出力が
   出ている間に `echo` が実行できる。
2. `jobs` に running のジョブが見える。
3. `fg` で待つとジョブが終わり、結果（slow done）と
   ステータスが取れる。
4. crash.elf を bg で走らせるとフォルトして done (status=-2)
   になり、Nish は無事で次のコマンドが打てる。
5. uprog.elf（対話型）を bg で走らせると入力待ちで stopped に
   なり、fg にすると入力を受け付けて普通に使える。

slow.elf はテストの道具: uptime を見ながら約 300ms ごとに
`slow i/N` を出し、最後に `slow done` と出して引数の
ステータス（既定 0）で終わる。crash.elf は開始を出してから
未割り当ての住所を触って落ちる。
