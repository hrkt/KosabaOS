# KosabaOS システムコール仕様 (v1)

状態: FS 再設計 段4 (ディレクトリ + 単一名前空間) と
exec 多段化に合わせて改訂し、カーネルログ (klog_read = 30)
と uptime (31)、オーディオ (audio_open / audio_write /
audio_close = 40〜42、Ikesu 段2の確定仕様) を追加
(2026-11-06)。仕様はこの開発の中で自分たちで決める
もので、必要になったらここを更新して育てる。想定する主な
利用者は、将来 KosabaOS 上で動かす IwaC と、IwaC が生成する
プログラム。

## 呼び出し方

- ユーザーモードのプログラムが `ecall` を実行すると、
  カーネルのトラップハンドラに制御が移る
- 番号は `a7`、引数は `a0`、`a1`、`a2`、戻り値は `a0`
- 処理が終わると、プログラムは `ecall` の次の命令から再開する
- 文字列やバッファはユーザーメモリへのポインタで渡す。
  カーネルは現在のプログラムに割り当てられた領域の範囲内で
  だけ読み書きする

## 番号付けの方針

- **一度割り当てた番号は振り直さない。廃止した番号も再利用
  しない** (ABI の安定のため。プログラムは番号でコンパイル
  されるので、番号の意味が変わると静かに壊れる)
- 番号は意味のブロックで割り当てる。ブロックの途中や
  ブロック間に空き (予約) があってよい (連番でなくてよい)
- **この一覧が番号の正本**。新しい syscall は、まずここに
  追記して番号を確保してから実装する

## パスの規則 (段4)

- パスは '/' 区切り。絶対パス ('/' 始まり) と、cwd からの
  相対パスの両方を受け付ける。解決と正規化はカーネル側の
  共通処理: '//' と '.' は畳み、'..' は親へ (ルートの親は
  ルート自身)
- 上限: パスの要素 1 つは 31 文字まで、パス全体は 128
  文字まで。超えたら -1
- cwd はカーネルがタスクごとに持ち (正規化済みの絶対
  パス文字列)、exec で子へ引き継がれる。カーネルから
  直接起動されたプログラムはルートから始まる
- RAM FS は木の幹で、SD カード (FAT32) は `/sd` に固定
  マウントされる (doc/sd-design.md)。`/sd` の配下でも
  create / write / unlink / mkdir / rmdir が RAM FS と同じ
  意味づけで使える (書き込み対応、doc/sd-write-design.md)。
  名前は 8.3 形式のみ。chdir は /sd の中へも入れる。
  SD からの exec は v1 の対象外 (-1)
- カードやドライバが無い環境でも、/sd への操作は -1 に
  なるだけで、他のパスへの影響はない

- fd には読み用 (open) と書き用 (create) の区別があり、
  逆向きの操作は -1 になる。fd 番号は exec の段ごとの
  テーブル内での番号 (exec の規則を参照)
- create で作るファイルは、書くたびに必要な分だけ育つ
  (ブロックチェーン方式、doc/fs-design.md)。上限はファイル
  ごとではなく arena 全体を全ファイルで分け合う形で、
  virt は 8MB、K210 は 256KB。write は入る分だけ書いて、
  書けたバイト数を返す

- 未定義の番号を呼んだら、戻り値として -1 を返して
  プログラムは続行する (落とさない)
- ユーザープログラムがメモリ保護に違反したら、そのプログラムは
  終了させてカーネルに帰る (カーネル自体は落とさない)

## プログラムの入口の約束 (argc / argv)

プログラムが起動するとき (カーネルからの直接起動でも exec
でも)、入口では次の約束で引数を受け取る:

- a0 = argc、a1 = argv (文字列へのポインタの配列。
  argv[argc] は NULL)。C の入口なら `_start(int argc, char **argv)`
  の形で受けられる
- 文字列と argv 配列はスタックの末尾に置かれ、sp は argv 配列の
  先頭を指す (16 バイト境界)
- exec の a1 は空白区切りの文字列 1 本で、そのまま argv の要素に
  なる (先頭の要素が argv[0])。Nish の `run 名前 引数...` は
  「名前＋引数」の並び全体を渡すので、argv[0] はプログラム名に
  なる。引用符やエスケープは扱わない
- 上限: 引数文字列は 511 バイトまで、要素は 16 個まで
- 引数が渡されなかった場合は argc = 1、argv[0] = プログラム名
  (カーネルからの直接起動も同じ)
- 浮動小数点: プログラムは FPU が使える状態 (sstatus.FS =
  Initial、fcsr は初期値) で始まる (exec でもカーネルからの
  直接起動でも同じ)。ただし FP レジスタの中身は exec を
  またいで保存されない。同時に走るユーザープログラムは
  1 本という現行モデルの割り切りで、親が FP を使ったまま
  exec すると、戻ってきたときにレジスタは子の残した値に
  なっている

## exec の規則

- exec は多段に重ねられる (exec の中で exec を呼んでよい)。
  同時に走るのは最上段の 1 プログラムだけで、下の段は
  メモリごと凍結される
- 深さの上限はメモリ (ページプール) の残量で決まる。
  暴走防止の sanity として 16 段までとし、達した exec
  (およびプールが尽きて子のページが取れない exec) は
  -1 を返す
- exec で子プログラムが動いている間、親プログラムのメモリは
  そのまま保たれる (仮想アドレスは全段で同じ場所を、段ごとに
  割り当てられた物理ページで差し替えて使う)
- 子が exit するか保護違反で終わると、親は exec の呼び出しから
  戻って続きを実行する。戻り値は子の終了ステータス (exit の
  a0) で、保護違反なら -2。ステータスは 0 以上を使うこと
  (-1 / -2 は exec 側の意味と重なるため)。ステータスと
  異常 (-2) の伝播は 1 段ずつで、一気に根元へは飛ばない
- fd テーブルは exec の段ごとに持つ。子は空のテーブルで
  始まり、親が開いたファイルは親の段に残るので、子が
  終わっても親はそのまま使い続けられる (旧仕様の
  「exec を呼ぶと開いていたファイルはすべて閉じられる」
  は廃止。exec 多段化、2026-11-06)
- cwd は子へ引き継がれる。子が chdir しても、親に戻ると
  親の cwd に復元される (段4)

## カーネルログ

- カーネルは出来事を固定長 (16KB) のリングバッファに
  テキストで残す (Linux の printk + dmesg の考え方)。
  1 行ごとに `[秒] ` の接頭辞 (起動以来の秒数 = tick) が付く
- 残すのはカーネル自身の出来事: 起動時の基本情報
  (ページプールの総数など)、exec の失敗理由 (プール
  枯渇、深さの上限)、ユーザープログラムの異常終了、
  SD のマウントなど。exec の戻り値 (-1) だけでは理由が
  区別できないので、理由はこちらで追えるようにする。
  ユーザープログラムの出力はログに入らない
- バッファがいっぱいになったら古い分から上書きされる。
  klog_read のオフセットは「起動以来の通し位置」で、
  上書き済みの位置を指定したら最古の残存位置から読む
- 読み出し口は klog_read (30) で、Nish の `dmesg`
  コマンドがそれを使って古い順に表示する
- カーネルのメッセージはコンソールにも同時に出る
  (従来の見え方は変わらない)。例外は毎秒の tick 表示で、
  あれはコンソールだけに出し、ログには残さない
  (1 秒ごとに 1 行たまるとログが tick で埋まるため)

## メモリの約束

- ユーザープログラムの住所の約束:
  コード 0x40000000 (読み + 実行)、データ 0x40200000
  (読み書き)、スタックは末尾寄せ (読み書き)。
  書ける場所と実行できる場所を分ける (W^X)
- 領域の大きさとスタック末尾はボードごと (board.h):
  virt はコード 2MB / データ 4MB / スタック 2MB (末尾 0x40800000)、
  K210 はコード 1MB / データ 1MB / スタック 512KB (末尾 0x40600000)。
  virt のデータが 4MB なのは IwaC のセルフホスト用 (2026-11-03 決定)
- 上の大きさは仮想アドレスの枠 (上限) で、物理メモリの付き方は
  ページ単位の実需割り当て (exec 多段化): コードとデータは
  ELF のセグメントが触るページだけを割り当て、スタックは
  小さく始めてページフォルトで枠の上限まで伸びる
- 使えるのは自分の 3 領域だけ。
  カーネルのメモリはページテーブルの U ビットなしでは
  ユーザーモードから触れない
