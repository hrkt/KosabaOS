# KosabaOS システムコール仕様 (v1)

状態: ステップ 6 のシェル実装に合わせて v0 から拡張した。
仕様はこの開発の中で自分たちで決めるもので、必要になったら
ここを更新して育てる。想定する主な利用者は、将来 KosabaOS 上で
動かす IwaC と、IwaC が生成するプログラム。

## 呼び出し方

- ユーザーモードのプログラムが `ecall` を実行すると、
  カーネルのトラップハンドラに制御が移る
- 番号は `a7`、引数は `a0`、`a1`、`a2`、戻り値は `a0`
- 処理が終わると、プログラムは `ecall` の次の命令から再開する
- 文字列やバッファはユーザーメモリへのポインタで渡す。
  カーネルは現在のプログラムに割り当てられた領域の範囲内で
  だけ読み書きする

## 一覧

| 番号 | 名前 | 引数 | 戻り値 | 意味 |
| --- | --- | --- | --- | --- |
| 1 | putc | a0 = 文字コード | 0 | コンソールに 1 文字出す |
| 2 | getc | なし | a0 = 文字コード | コンソールから 1 文字受け取る (届くまで待つ) |
| 3 | exit | なし | (戻らない) | プログラムを終了する (下記の exec の規則も参照) |
| 4 | open | a0 = 名前へのポインタ | a0 = fd (0 以上) / -1 | ファイルを開く |
| 5 | read | a0 = fd、a1 = バッファ、a2 = 最大バイト数 | a0 = 読めたバイト数 (0 = 終端) / -1 | ファイルから読む。読み位置は fd ごとに進む |
| 6 | close | a0 = fd | 0 / -1 | ファイルを閉じる |
| 7 | readdir | a0 = 番号 (0 始まり)、a1 = 名前バッファ (32 バイト) | 1 = 書いた / 0 = もう無い | ファイル一覧を 1 件ずつ得る |
| 8 | exec | a0 = 名前へのポインタ | プログラム終了後に戻る: 0 = 正常終了 / -2 = 保護違反で終了 / -1 = 起動できなかった | 名前でプログラムを実行する |
| 9 | create | a0 = 名前へのポインタ | a0 = fd (書き込み用) / -1 | ファイルを作る (同名があれば空にする) |
| 10 | write | a0 = fd、a1 = バッファ、a2 = バイト数 | a0 = 書けたバイト数 / -1 | ファイルへ末尾から書く |
| 11 | tasks | a0 = バッファ (256 バイト) | a0 = 書いたバイト数 | カーネルタスクの一覧をテキストで得る (ps 用) |

- fd には読み用 (open) と書き用 (create) の区別があり、
  逆向きの操作は -1 になる
- create で作るファイルは 32KB まで書ける (v1 の割り切り。
  作成時に arena から領域を確保する)。write は入る分だけ
  書いて、書けたバイト数を返す

- 未定義の番号を呼んだら、戻り値として -1 を返して
  プログラムは続行する (落とさない)
- ユーザープログラムがメモリ保護に違反したら、そのプログラムは
  終了させてカーネルに帰る (カーネル自体は落とさない)

## exec の規則 (v1 の割り切り)

- exec は 1 段まで (exec の中で exec を呼んだら -1 が返る)
- exec で子プログラムが動いている間、親プログラムのメモリは
  そのまま保たれる (仮想アドレスは同じ場所を、別の物理メモリで
  差し替えて使う)
- 子が exit するか保護違反で終わると、親は exec の呼び出しから
  戻って続きを実行する
- exec を呼ぶと、開いていたファイルはすべて閉じられる

## メモリの約束

- ユーザープログラムの住所の約束:
  コード 0x40000000 (読み + 実行)、データ 0x40200000
  (読み書き)、スタックは末尾寄せ (読み書き)。
  書ける場所と実行できる場所を分ける (W^X)
- 領域の大きさとスタック末尾はボードごと (board.h):
  virt はコード 2MB / データ 4MB / スタック 2MB (末尾 0x40800000)、
  K210 はコード 1MB / データ 1MB / スタック 512KB (末尾 0x40600000)。
  virt のデータが 4MB なのは IwaC のセルフホスト用 (2026-11-03 決定)
- 使えるのは自分の 3 領域だけ。
  カーネルのメモリはページテーブルの U ビットなしでは
  ユーザーモードから触れない
