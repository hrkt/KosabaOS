ステップ 4ユーザーモードとシステムコール

狙い：「OS の上でプログラムが動く」形を作ること。プログラムは権限の弱い U モードで動き、メモリ保護（ステップ 3）によって自分の領域しか触れません。

システムコールの仕様は自分たちで決めた

約束はシンプルです：番号を a7、引数と戻り値を a0 に入れ、 ecall を実行する。仕様書は doc/syscalls.md に v0 として残しました。

番号名前意味
1putcコンソールに 1 文字出す
2getcコンソールから 1 文字受け取る（届くまで待つ）
3exitプログラムを終了し、カーネルに帰る

知らない番号を呼ばれたら -1 を返して続けさせる、プログラムが保護違反をしたら そのプログラムだけを終了させる、という決まりも含めてあります。 将来この窓口を使うのが、自作 C コンパイラ IwaC と、 IwaC が作るプログラムたちです。

行き来の仕組み

カーネルが文脈
（戻り先など）を退避
→ sret で降りる →
U モードで
プログラムが動く
→ ecall / exit →
カーネルが処理し、
文脈を復元して戻る

細部の工夫：U モードから割り込みが来たとき、スタックはユーザー側を指したままなので、 sscratch という受け渡し場所を使ってカーネル専用のスタックに 乗り換えてから受けます。実測の往復ログです（u キーで起動）：

[kernel] starting user program ('q' quits it)
hello from user mode!     ← ユーザープログラムが syscall 経由で出した挨拶
tick 2                    ← 実行中もタイマ割り込みは届いている
a                         ← ユーザー側の echo
[kernel] back from user program   ← 'q' で exit して戻った
b                         ← カーネル側の echo が再開

つまずき 2 件

症状原因
最初の ecall が「番号 0」と判定される退避したレジスタの並びで、a7 の位置を 1 つ数え間違えていた
プログラムの途中から実行が始まるバイナリの先頭が入口 _start になるとは限らない（リンカは関数を宣言順に並べない）。.text.start という専用の置き場所で先頭に固定した

ステップ 5マルチタスク

狙い：実行の流れ（タスク）を複数持ち、切り替えながら全部を進めること。 各タスクは自分のスタックと「文脈」（再開に必要なレジスタの組）を持ち、 スケジューラが順番に選んで交代します。

切り替えのきっかけは 2 種類

方式きっかけデモの出力（実測）
協調的タスクが自分から yield（譲る）ABABABAB…（1 文字ごとに譲るので完全な交互）
プリエンプティブタイマ割り込み（100ms ごと）が強制的に交代AAAAAAAAA BBBBBBBBB AAAAAAAAA…（約 9 文字の塊で交互）

タイマ割り込みは 100ms 間隔に変えました（tick の表示は 10 回に 1 回にして、 1 秒に 1 行の見た目は維持）。トラップをまたいで切り替えるときは、 CPU に 1 組しかない sepc / sstatus をタスクごとに 退避・復元するのが肝です。デモは m キーで起動し、 両方の幕が終わると通常の echo に戻ります。

つまずき：「割り込み禁止」のまま走り出したタスク

最初の実装では、第 2 幕で片方のタスクが最後まで走り切ってしまいました。 切り替え回数を数えるとスケジューラ自体は毎回切り替わっていて、 切替の流れを追って判明した原因はこれです： トラップ処理の最中から初めて起動されたタスクは、割り込み禁止 （sstatus.SIE = 0）の状態を引き継いで走り出し、タイマ割り込みを 永遠に受けられなかった。 「通常の文脈に戻るとき（yield の出口と、タスクの入口）で割り込み許可を 立て直す」という決まりにして解決しました。

この段階のタスクはカーネルの中（S モード）の流れで、 ページテーブルは全タスクで共有です。タスクごとにページを持ち、 U モードのプログラム自体をタスク化するのは、ステップ 6 側の発展として残しています。

検証のしかた — 自動テストと実機ならぬ WSL2

  • test.sh が 4 シナリオ（起動、echo とフォルトデモ、ユーザープログラムの往復、 マルチタスクの両幕）を自動で実行し、ALL PASS を確認しています
  • 開発環境のほかに、利用者自身の WSL2（ThinkPad、QEMU 10.2 / OpenSBI 1.8 という だいぶ新しい組み合わせ）でもビルド・起動・全シナリオ PASS を確認済みです。 バージョンが変わっても壊れていないことの実証になりました（手順は doc/wsl2-guide.md）

ここまでの到達点と、次

  • KosabaOS は、C で書かれ、割り込みとメモリ保護を持ち、U モードのプログラムを システムコールで動かせ、複数のタスクを切り替えられるカーネルになった
  • 次のステップ 6：ELF ローダ（ファイルをプログラムとして読み込む）→ RAM ファイルシステム → ユーザー空間のシェル → OS の上で IwaC を動かして Hello World をコンパイル → 実機へ、という全体ゴールへの接続
  • IwaC 側も並行して進んでいます：本物の uart_puts / uart_putc の ソースが IwaC でコンパイルできるところまで到達済みです
