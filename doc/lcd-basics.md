# LCD はどうやって光るのか — 読んで学ぶためのメモ

これは仕様書ではなく、概念を腹落ちさせるための学習用ドキュメント。
K210 の LCD ドライバ (開発メモは `k210-lcd-driver.md`) を読むときに
「そもそも何をしているのか」で迷ったら、ここに戻ってくる。

## 全体像

画面を光らせる仕事は、大きく 3 人で分担している。

| 役者 | 実物 | 仕事 |
|---|---|---|
| CPU | K210 | 「何を描くか」を決めて指示を出す |
| SPI0 | K210 の中の通信係 | 指示と絵のデータを電気信号にして運ぶ |
| LCD コントローラ | パネル裏の ST7789 というチップ | 届いたデータを覚えて、液晶を光らせ続ける |

大事なのは、**CPU が画面を光らせ続けているのではない**こと。
CPU は「この範囲をこの色で塗れ」という指示と材料を ST7789 に
渡すだけ。あとは ST7789 が自分のメモリに絵を覚えて、勝手に
表示し続ける。だから CPU が止まっても画面は残るし、時計の
数字を書き換えたいときだけ CPU が仕事をすればいい。

流れを郵便に例えると:

- **コマンド** = 封筒の宛名書き。「窓を設定する仕事だよ」
  「絵のデータを送るから受け取って」といった仕事の種類を指定する。
- **パラメータ** = 封筒の中の注文書。「窓は左上 (20,20) から
  右下 (79,79) まで」のような、コマンドに付随する具体的な数値。
- **画素データ** = 材料そのもの。色の並びを大量に送る。

## ST7789 の中: GRAM とアドレスカウンタ

ST7789 の中には **GRAM** という、画面 1 枚分のメモリがある
(このパネルでは 240 列 × 320 行、1 画素 2 バイト)。
画面に出ている絵 = GRAM の中身、そのものだと思ってよい。

GRAM への書き込みは「窓」と「自動で進むペン」でできている。

1. **窓 (window)** を決める: CASET コマンドで列 (横) の範囲、
   RASET コマンドで行 (縦) の範囲を指定する。
   CASET は Column Address SET、RASET は Row Address SET の略。
2. **RAMWR** コマンドを送ると書き込み開始。RAMWR は
   RAM Write (メモリへ書け) の略。
3. あとは色データを流し込むだけ。ST7789 の中の
   **アドレスカウンタ** というペンが、1 画素書くたびに自動で
   次の位置へ進む。窓の右端まで来たら次の行の左端へ、
   窓の下端まで来たら左上へ戻る。

この「ペンが勝手に進む」仕掛けのおかげで、CPU は座標を
いちいち言わず色だけを流し込めば、面が塗れる。
逆に言うと、**流し込みの途中で話が途切れると、ペンの位置が
ずれて絵が化ける**。ドライバが「窓 1 つにつき 1 本の連続
ストリームで送る」のはそのため。

## 色の表し方: RGB565

1 画素の色は 16 ビット (2 バイト) で表す。赤 5 ビット、
緑 6 ビット、青 5 ビットを詰めた形で、**RGB565** と呼ばれる
(緑だけ 1 ビット多いのは、人間の目が緑に一番敏感だから、
と言われる)。赤を最大にするなら `11111 000000 00000` =
0xF800。ドライバの `LCD_RGB(r, g, b)` マクロは、普通の
0〜255 の色指定をこの詰め方へ変換している。
パネル側には「これから RGB565 で送る」と COLMOD コマンド
(0x3A、色の形式の宣言) のパラメータ 0x55 で宣言する。

## 向きの指定: MADCTL

パネルは物理的には縦長 (240×320) でも、GRAM の読み方を
変えれば横向き (320×240) の画面として使える。その読み方を
決めるのが **MADCTL** (Memory Access Control, 0x36) という
設定レジスタで、パラメータ 1 バイトの中のビットが
「行と列を入れ替えるか (MV)」「左右を反転するか (MX)」
「上下を反転するか (MY)」を決める。横向きにしたいときの
組み合わせの 1 つが 0xA0。窓の座標や画素の流し込む順序は
常に「今の向きの画面」の座標で考える。

## 通信の実物: ピンと信号

CPU と ST7789 の間は、何本かの銅線 (ピン) でつながっている。

- **CS (Chip Select)**: 「今から君に話す」という合図の線。
  合図が有効な間だけ、相手は耳を澄ます。合図を下ろすと
  会話は終わり。SPI0 には相手が 4 つまでつなげて、うちの
  LCD は 3 番 (SS3 = Slave Select 3) につながっている。
- **CLK (Clock)**: 通信の拍子を取る線。「せーの」で 1 ビット
  (あるいは同時並行で数ビット) ずつ送るための合図。
- **データ線**: 実際にビットが流れる線。このボードでは 8 本
  同時に使う (後述の octal)。
- **DC (Data/Command)**: 「今流れているのはコマンド (0) か、
  データ (1) か」を示す番外の線。封筒の宛名書きと中身を
  区別するための目印だと思えばいい。
- **RST (Reset)**: ST7789 を電源投入直後の状態に戻す線。
  最初にこれを叩いてから初期化列 (起動の挨拶のような
  コマンドの並び) を送る。

## なぜ SPI の octal モードなのか

本来 ST7789 は「8080 バス」という、8 本のデータ線を同時に
使う古い流儀の接続を想定している。ところが K210 の SPI0 は
普通の SPI (データ線 1 本) の進化版で、データ線を 8 本使う
**octal モード** (octal = 8 本) があり、これで 8080 バスの
真似ができる。MaixPy も KosabaOS のドライバもこの手を使う。

K210 の SPI0 は DesignWare SSI という設計の通信係で、
1 回の転送は最大で 3 つの **フェーズ** (区間) からなる。

1. **instruction フェーズ**: 転送の最初に置く短い合図。
   ドライバはここに LCD コマンド (1 バイト) を載せる。
2. **address フェーズ**: 次に置く位置情報の区間。ドライバは
   ここにパラメータと画素データを載せる。
3. **data フェーズ**: 本体データの区間 (この使い方では使わない)。

「コマンドは instruction、データは address」という載せ方の
指定が、SPI_AITM_AS_FRAME_FORMAT という転送モードで、
レジスタ (後述) の spi_ctrlr0 に書く。開発メモの落とし穴に
ある「パラメータは 8bit フェーズでは届かず 16bit フェーズで
送る」は、この address フェーズの長さ設定の話。

転送の速さは **baudr** という分周値で決める。元の時計
(SPI0 の入力クロック 390MHz) を baudr で割ったものが
CLK の速さになる。baudr 26 なら 15MHz、つまり 1 秒に
1500 万回、8 本並行でバイトが流れる。

CPU から SPI0 へ渡すデータは **FIFO** という小さな待ち行列
(32 個分) にいったん積む。通信係は行列から順に取り出して
線へ流す。CPU は行列に空きができたら次の分を足す、
という繰り返しで大量の画素を送る (これをポーリング方式と
言う。行列の残りを自分で見張るやり方)。MaixPy は DMA
(行列への積み込みを専門の係に任せる仕組み) を使っているが、
結果として線に流れるものは同じ。

## K210 側の都合: FPIOA / GPIOHS / sysctl

K210 のピンは「何にでもなれる」汎用ピンで、役割は後から決める。

- **FPIOA** (Field Programmable IO Array): ピンの役割分担表を
  書く場所。「IO36 は SPI0 の CS にして」「IO37 は自由に
  ON/OFF できるピンにして」と 1 ピンずつ割り当てる。
  書き値には役割番号に加えて、電気的な強さ (ds) や
  出力を有効にする旗 (oe_en) をビットで重ねる。
- **GPIOHS** (GPIO High Speed): FPIOA で「自由なピン」に
  割り当てたピンを、プログラムから直接 ON/OFF するための
  係。LCD の RST と DC はこれで叩く (通信係の仕事ではない
  単なる信号線だから)。
- **sysctl** (System Control): チップ全体の管理係。クロックの
  元になる PLL (周波数を作る回路) の設定、各係へのクロック
  供給の開閉、雑多な全体設定を持つ。LCD 関係では
  「SPI0 にクロックを流す」開閉と、**spi0_dvp_data** という
  特別な設定が要る。これは「SPI0 のデータ線を、カメラ用
  (DVP) のピン群へ出す」という配線切替で、このボードの LCD は
  そちら側に配線されている。FPIOA に SPI0 のデータ線の
  役割がそもそも無いのは、この切替が前提だから。

## レジスタという言葉

このメモにも開発メモにも「〜レジスタ (0x50440054 の bit10)」
のような書き方が出てくる。**レジスタ**とは、周辺の係
(SPI0 や sysctl など) が持っている「設定や状態のための
小さなメモリ」のこと。普通のメモリと同じくアドレスが
付いていて、CPU は読み書きできる。ただし中身はただの
数値ではなく、ビット 1 つ 1 つがスイッチや状態表示に
つながっている。だから「bit10 を立てる」のような操作が
「その機能のスイッチを入れる」意味になる。

## 用語まとめ

| 用語 | 意味 |
|---|---|
| ST7789 | LCD パネルの裏にいるコントローラチップ。GRAM を持ち、描画を引き受ける |
| GRAM | ST7789 の中の画面 1 枚分のメモリ |
| コマンド / パラメータ | 仕事の種類を指定する 1 バイト / それに付随する数値列 |
| CASET / RASET | 窓の列範囲 / 行範囲を設定するコマンド |
| RAMWR | 「これから画素を流す」コマンド。以後はアドレスカウンタが自動で進む |
| COLMOD | 色の形式 (RGB565 など) を宣言するコマンド |
| MADCTL | GRAM の読み方 (回転・反転) を決める設定 |
| RGB565 | 赤 5・緑 6・青 5 ビットで 1 画素を表す形式 |
| SPI / octal | クロックに合わせてビットを送る通信方式 / データ線 8 本の版 |
| フェーズ | 1 回の転送の中の区間 (instruction / address / data) |
| baudr | SPI のクロックを作る分周値。大きいほど遅い |
| FIFO | 送信データを一時的に溜める待ち行列 (32 個分) |
| FPIOA | K210 のピンの役割分担表を書く場所 |
| GPIOHS | プログラムから直接 ON/OFF するピンの係 |
| sysctl | チップ全体のクロックや雑多な設定を持つ管理係 |
| レジスタ | 周辺の係が持つ、ビット単位で意味のある設定・状態メモリ |
| DC / CS / RST | データかコマンドかを示す線 / 相手を選ぶ線 / リセット線 |
