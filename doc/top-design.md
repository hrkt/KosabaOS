# top-design.md — top 風ツールの設計

Unix の top のような「いま誰が CPU を使っているか」を
眺める道具を作る。材料は2層に分かれる: カーネル側の
タスク (proc.c) と、ユーザープログラムである走者
(trap.c の前面 + ジョブ)。

## 段1: CPU 積算と名前 (済)

- カーネルタスク: 切り替えのたび (schedule の入口) に
  time CSR の差分を今のタスクへ精算する。寝ている
  タスクの分は数えない。寝る直前の働きは task_sleep_ms
  の入口で先に精算する (SLEEPING にしてからでは
  跳ねられるため)
- 走者: 切り替え地点 (restore_runner) と exec の段の
  出入りで精算する。前面は段ごとに名前 (exec の引数の
  basename、段0 は "nish") と CPU を持つ。前面の
  getc 待ちと job_wait のブロック中、止まっている
  ジョブの時間は数えない (待ちは CPU 使用ではない)。
  getc 待ちは旗の上げ下げで区切って精算する
- 出力: SYS_TASKS (11) のテキストを拡張する。
  カーネルタスクの行は従来の形の後ろに `cpu=ミリ秒`
  を足すだけ (既存の照合を壊さない)。後ろに走者の行
  `run N: 名前 状態 cpu=ミリ秒` が続く。Nish の ps が
  そのまま表示する (バッファは 1024 へ)
- 既知の割り切り: タスク 0 (kmain の文脈) の cpu は
  走者の syscall やポーリング待ちの回転も含む「宿主」
  の数字になる。プログラム単位の精密な数字は run の
  行を見る

## 段2: top のための土台 (実装済み)

- sleep_ms (34): 走者が指定ミリ秒寝る。前面は getc
  待ちと同じ作法 (ecall の位置で保存して再開時に
  やり直し)、ジョブは新状態 JOB_SLEEPING で止める。
  寝ている間は CPU 積算に数えない。誰も走れないときは
  ハンドラ内で sched_poll しながら待つ
- getc (2) のタイムアウト拡張: a1 = タイムアウト
  (ミリ秒、0 = 従来どおり無限待ち)、持ち主の待ちに
  だけ付き、過ぎれば -1。期限は fg_save.getc_until に
  持ち、ジョブへ番が移っても数え直さない
- 起床の配線で 1 つ直したこと: 前面が getc 待ちの間、
  ジョブの番を決める走査が JOB_RUNNING だけを見て
  いたため、寝たジョブの起床が次のコマンド入力まで
  遅れた。runner_runnable (期限を過ぎた JOB_SLEEPING
  も実行可能) で見るよう統一した
- 検証プログラム: nap.elf (sleep_ms)、keywait.elf
  (getc タイムアウト)。test.sh シナリオ AN

## 段3: top.elf (予定)

- 1秒ごとに SYS_TASKS を読み直し、前回との差分から
  %CPU を出して画面を描き直す (ANSI の画面クリア)
- 終了は q キー。引数で回数を指定できるとテストが
  しやすい
