# 将来の検討事項 (future notes)

仕様 (doc/syscalls.md) にはまだ入れていないが、「使う実物が
現れたら検討する」と決めた項目の置き場。2026-11-03 に基本仕様
(v1 + 入口の約束 + FS のボード別サイズ) を一区切りとして
点検したときに挙がったもの。

## 1. create の予約方式 (FS) → 対応済み (2026-11-04)

当時は create の時点でファイルの上限 (ボード別の予約サイズ:
virt 4MB / K210 32KB) を arena から丸ごと確保していたため、
大きなファイルを複数作ると arena が尽きた。

IwaC の分割コンパイル等、複数ファイルを扱う道具立ての
見通しを受けて FS を再設計した (doc/fs-design.md、案A
ブロックチェーン方式)。段1 で予約方式そのものを廃止し、
ファイルは書いた分だけブロックの鎖で育つようになった。
残りは同設計の段2 (ファイル数 64 と unlink) と段3
(必要になったら stat / seek)。

## 2. exec の多段化 → 実施済み (2026-11-06)

(実施前の状況の記録) 当時の exec は 1 段まで (割り切りとして syscalls.md に明記)。
Nish → ドライバ → コンパイラのような 2 段の起動はできない。
親の状態の退避先と子の物理領域は 1 組しかないためで、多段化
には退避のスタック化と領域の組を増やす必要がある。特に
K210 は汎用 SRAM 6MB を現行配置で使い切っており、子の組を
増やす余地がない (virt だけ多段化するか、領域を動的に
切り分けるかが論点)。

回避策として、駆動役を Nish 自身の機能にする手もある、と
していたが、Misoni をプログラムとして書く段になって実需が
出たため、多段化の計画を doc/exec-multilevel.md に起こした
(退避のスタック化、fd テーブルの段ごと化、物理メモリは
固定セットでなくページ単位の実需割り当てにする方式。
深さはプール次第、K210 でも小さいプログラムの連鎖なら
数段を目指す)。

2026-11-06 に計画どおり実施済み (段A 退避と fd、段B ページ
プール化とスタック fault 伸長、段C K210 のプール化)。
仕様は syscalls.md の exec の規則、実施の記録は
doc/exec-multilevel.md の末尾を参照。

## 3. 子の終了ステータス → 対応済み (2026-11-03)

exec の戻り値は正常終了なら常に 0 で、exit に引数がなかった。
ドライバが「前の段が成功したか」で分岐できるよう、exit の
a0 を終了ステータスとし、exec の戻り値として親に伝えるよう
変更した (0 = 正常、-1 = 起動失敗、-2 = 保護違反は従来どおり
予約)。Nish の run は 0 でないステータスを表示する。
test.sh シナリオ K で確認。

## 4. 次フェーズの将来アイデア (2026-11-07 のメモ)

ジョブ制御 (スケジューラ段3) まで main に着いた時点で、
ユーザーが「全部楽しいからまずメモして」と挙げた候補。
実需と面白さが重なったものから順に設計を起こす。

1. **画面をユーザープログラムに開く (描画 syscall → 窓)**
   ← 今回着手する案1。LCD は今はカーネル (時計) だけのもの。
   描画 syscall でユーザープログラムに開き、やがて走者
   (ジョブ) ごとに窓を持たせる。ジョブと窓を対にし、
   コンソールの仲裁 (持ち主) がそのまま窓のフォーカスに
   なる。「並行で走る」が目で見える形にするのが狙い。
   設計は doc/gfx-design.md。
2. **音を本物にする (I2S ドライバ)**。オーディオ syscall
   (40〜42) は両ボード共通のダミーのままで、実体が無い。
   K210 の I2S ドライバを書いて本物の音を出す。Ikesu 側の
   段1 (ドライバ)・段6 (実機で聴く) と接続する話。
3. **単独で使えるコンピュータ軸**。SD からの exec 解禁
   (今は v1 の対象外で -1) と、キーボード入力デバイス。
   プログラムを埋め込まずカードから読み、シリアル越しで
   なく手元のキーで操作できるようにする。「目の前に
   座れる自作コンピュータ」への軸。
4. **小粒**: Maixduino の ESP32 経由で NTP を取り、RTC を
   自動で合わせる (doc/time.md で「将来の話」と置いた件)。
   K210 のカメラを LCD に映すデモ (鏡 / ビューファインダ)。

## あえて入れていないもの

ファイル削除 (unlink)、seek、時刻の取得、メモリの動的拡張
(brk 相当) は、使う実物が見えるまで入れない。仕様は実物に
引っ張られて育てるのがこの OS の進め方 (write 系は IwaC の
ため、FS 拡大はセルフホストのため、argv はリンカ案のため
に足された)。
