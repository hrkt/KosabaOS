# スクリーンセーバー設計

KosabaOS を置き時計として電源を入れっぱなしにすると、LCD
に同じ絵 (特に時計帯の時刻表示) が長時間残り、残像が
出る。その対策として、入力の無い時間が続いたら表示を
動かすスクリーンセーバーを入れる。ユーザーの決定で
**二段構え**にする:

- **段1 (帯内)**: 一定時間入力が無いと、時計帯
  (y216..239) の中で時刻表示がゆっくり移動し始める。
  ユーザープログラムの窓には一切触らないので、プログ
  ラム実行中でも有効でよい。
- **段2 (全面)**: さらに長くアイドルが続き、**かつ
  何も走っていないときだけ**、画面全体に大きな時刻が
  ゆっくり漂うセーバーに移る。入力があれば即復帰する。

## 置き場所

判定と描画は時計タスク (proc.c の clock_body、約 1 秒
周期) に相乗りする。状態機械は新規の saver.c / saver.h
に置く。時計タスクは毎秒 saver_tick(seconds) を呼び、
戻り値で通常の帯描画 (lcd_tick_draw) をするかどうかを
決める (段2 の間は帯描画を抑止する。帯は段2 の絵に
覆われているため)。

新規 syscall は無い (doc/syscalls.md は変更なし)。

## アイドル計測

- 物差しは生の time CSR (r_time())。trap.c の tick や
  trap_uptime_ms は、割り込みが滞る入力待ちでは一緒に
  滞ることがある (スケジューラ段1 で sleep の物差しを
  こちらに替えたのと同じ判断)。セーバーが効くべき場面
  はまさにその入力待ちなので、こちらで測る。
- 「活動」は saver_note_activity() で記録する。呼ぶの
  は次の 2 箇所だけ:
  - trap.c の SYS_GETC が文字を返したとき (コンソール
    の持ち主の成功のみ。bg ジョブは getc で成功しない
    ので、自然に数に入らない)
  - kernel.c の console_getc が文字を返したとき
    (カーネルコンソールのキー入力と行入力の両方を含む)
- 活動があったときのセーバー終了と復帰描画は、
  saver_note_activity の中でその場で行う。時計タスク
  の次の起床 (最大 1 秒後) まで遅らせないのは、キー
  入力で起動されたプログラムが描いた絵を、遅れて来た
  復帰描画が消してしまう事故を避けるため。描画
  syscall が trap 文脈から LCD を描くのと同じ土俵で
  ある。

## 段2 の「何も走っていない」の定義

LCD は書き込み専用でフレームバッファが無く、窓の中身
はカーネルが保持していないので再描画できない
(doc/gfx-design.md の前提)。だから段2 は、覆ってよい
画面しか無いときに限る。判定は次のとおり:

- trap.c が trap_saver_env() で走者層の状態を公開する:
  - bit0: ジョブが 1 つでも存在する (スロットが
    JOB_FREE でない。終わって回収待ちの JOB_DONE も
    「存在する」に数える — その窓はまだ画面に残って
    いるため)
  - bit1: 前面がシェルの入力待ち (console_owner == 0
    かつ exec_depth == 0 かつ、前面の持ち主が
    SYS_GETC の待ちの中にいる)
- 「SYS_GETC の待ちの中にいる」は、持ち主の getc
  ポーリングループの入口と出口で立てるフラグ
  (fg_getc_wait) で表す。前面でプログラムが実行中
  のときはもちろん、子プログラム (exec_depth > 0) が
  入力待ちのときも bit1 は立たない。
- カーネルコンソール側は kernel.c が担う: トップ
  レベルのキー待ちの間だけ saver_set_console_prompt(1)
  を立てる。't' の行入力やコマンドの実行中は立てない
  (打ちかけの行を全面で覆わないため)。
- **段2 の条件 = ジョブが無い AND (前面シェルの入力
  待ち OR カーネルコンソールのキー待ち)**。
- 段1 はこの条件を問わない (帯だけの話なので)。
- 段2 に入った後にジョブが始まることはない (ジョブの
  開始はキー入力 = 活動であり、その時点で段2 は
  終わっている)。

## 閾値

- 既定は 段1 = 無入力 60 秒、段2 = 無入力 300 秒
  (合計)。定数は saver.c の冒頭に集約する
  (SAVER_STAGE1_SEC / SAVER_STAGE2_SEC)。
- テストで実時間を待たない仕掛け: ビルド時に
  -DSAVER_TEST が付くと 段1 = 4 秒 / 段2 = 10 秒に
  差し替わる。build.sh は環境変数 SAVER_TEST が設定
  されていればそれを渡す。シナリオ AD (virt) と
  K23 (実機) は、このビルドで別途ビルドし直して使う
  (通常ビルドの閾値は変えない)。

## 描画の作法

### 段1

- 帯の中だけを動かす。lcd.c の tick 描画にオフセット
  の口 (lcd_tick_set_offset) を足し、セーバーが
  5 秒ごとに dx を +6 ずつ進め、端 (56) で折り返す。
  dy は 0..3 をゆっくり往復する。tick 文字は scale 3
  で 8 文字 144px 幅・21px 高、帯は 320x24 で、
  定位置 (118,216) からの移動余地はこの範囲。
- tick 描画は「前回描いた位置を地色で消してから描く」
  作りなので、オフセットを変えるだけで移動が実現
  する (前回位置の消去は lcd.c が最後に描いた位置を
  覚えて行うよう、小さく直す)。
- 段1 の間も秒の更新は毎秒続く。帯の描画権は従来
  どおり時計タスクで、セーバーはオフセットだけを差す。
- 終了時はオフセットを 0 に戻す。次の tick 描画が
  移動先を消して定位置に描き直す。

### 段2

- 入るとき: 全面を暗い地色 RGB(8,8,24) で消し、
  大きな時刻を描く。文字列は tick と同じ (壁時計が
  有効な間は "HH:MM:SS"、無ければ起動秒数)、
  scale は 4。
- 漂い: 位置は 4 秒ごとに (dx +9, dy +5) ずつ進み、
  収まる範囲で折り返す。毎秒、前の位置を地色で消して
  現在の位置に描き直す (秒の更新も兼ねる)。
- 終わるとき (活動があったとき) の復帰描画:
  1. gfx_desktop_repaint(): クライアント領域
     (時計帯より上) をデスクトップ色で消し、使用中の
     窓すべての枠・タイトルを描き直す
  2. lcd_tick_repaint(): 時計帯を地色で消し直し、
     TICK ラベルと時刻を定位置に描く
- **復帰で戻せないもの** (正直な線引き): 前面窓の
  中身に残っていた、終了済みプログラムの絵は段2 に
  入る時点で捨てる (Nish 自身は gfx に描かないので、
  シェルの待ち受け画面としての実害はない)。起動
  直後の飾り文字 (CONSOLE READY 等、クライアント
  領域に起動時だけ描かれるもの) も戻さない。復帰
  範囲は「デスクトップ色 + 枠・タイトル + 時計帯」
  まで。
- TICK ラベルの描画は lcd_tick_setup へ寄せる
  (従来は kernel.c が描いていた)。帯の再描画を
  lcd.c の中で閉じるためで、描くピクセルは変えない。

## ログ (検証の物差し)

遷移のたびに klog へ要約行を残す (ログ専用。gfx と
同じ流儀で、LCD のある環境でも同じ行が残るので、
dmesg 経由の検証は両環境で同じになる):

- `saver: stage1 on`
- `saver: stage2 on`
- `saver: off`

virt には LCD が無いので、シナリオはこの行の順序で
照合する。実機のピクセル (本当に動いて見えるか) は
目視が最終確認になる。

## 変更範囲

- 新規: saver.c / saver.h、doc/screensaver-design.md
  (本書)
- proc.c: clock_body から saver_tick を呼ぶ (帯描画の
  抑止判断を含む)
- trap.c: SYS_GETC 成功で saver_note_activity、
  fg_getc_wait フラグと trap_saver_env の公開
- kernel.c: console_getc 成功で saver_note_activity、
  トップレベルのキー待ちで saver_set_console_prompt。
  TICK ラベルの描画を lcd_tick_setup 側へ移す
- lcd.c / lcd.h (k210): lcd_tick_set_offset、最後に
  描いた位置の記憶、lcd_tick_repaint、段2 用の
  lcd_saver2_begin / lcd_saver2_draw
- gfx.c / gfx.h: gfx_desktop_repaint
- build.sh: saver.c の追加、SAVER_TEST の受け口
- doc/syscalls.md: 変更なし

## 検証

- virt シナリオ AD (SAVER_TEST ビルドで実施): 無入力で
  `saver: stage1 on` → `saver: stage2 on` の順に
  出ること、キー入力で `saver: off` になること、
  前面でプログラムが実行中は段2 に入らない (段1 には
  入る) こと。
- 実機 K23 (SAVER_TEST ビルドで実施): 同じ流れを
  dmesg で照合する。ピクセルの動きは目視の担当。
- 既存シナリオ (特に時計帯まわりの W・K16) に回帰が
  無いこと。
