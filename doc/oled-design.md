# OLED (SSD1306) 設計 — 基板2の第2画面

状態: 設計 (2026-11-19)。モジュールは購入済み・到着待ち。
対象は基板2 (Maixduino)。基板1は当面対象外 (ピンが違う)。

## 目的

0.96 インチ OLED を基板2の小さい第2画面として使う。
LCD (320x240) が「大きく出す画面」なのに対して、こちらは
常時そばに置く小さい表示: 時刻、状態の一行、ima の小さい版など。
用途の確定は後でよい。まずドライバを通す。

## 前提 (実測・資料で確認済みの事実)

- モジュール想定: SSD1306、128x64、モノクロ、I2C 接続 (4ピン:
  VCC / GND / SCL / SDA)。0.96 インチの一般的な姿。
- **Maixduino には I2C 専用ピンがある** (ピンアサイン表 V1.0):
  SCL = IO30、SDA = IO31。基板上に 4.7K のプルアップ付き、
  IO 電圧 3.3V、ヘッダに SCL / SDA のシルク印刷あり。
  → 配線は OLED の SCL→IO30、SDA→IO31、VCC→3.3V、GND→GND。
  プルアップは基板側にあるので外付け不要。
- IO30 / IO31 は KosabaOS の基板2構成では未使用
  (SD=IO26〜29、I2S=IO33〜35、LCD=IO36〜39、ESP32 CS=IO25、
  ESP32 EN=IO8)。衝突しない。
- K210 の I2C は DesignWare 系コントローラが3つ
  (I2C0 = 0x50280000、I2C1 = 0x50290000、I2C2 = 0x502A0000)。
  FPIOA 機能番号は I2C0_SCLK = 126 / I2C0_SDA = 127
  (I2C1 は 128 / 129)。使うのは I2C0 とする。
- レジスタ配置と初期化の式は Kendryte SDK (Apache-2.0、
  reference/ に保持) の i2c.h / i2c.c を参照する。
  コピーではなく、必要な分だけ自前で書く。

## 到着時に確認すること (未確認事項)

- I2C アドレス: 0x3C が一般的。0x3D のモジュールもある。
  基板裏のハンダジャンパ (SA0) で決まる。ドライバ側は
  定数1つで切り替えられるようにしておく。
- コントローラが SSD1306 か SH1106 か。SH1106 は 132 列で
  列オフセット 2 が要るなど初期化と転送が少し違う。
  動かなければこちらを疑う。
- SPI 版 (7ピン) でないこと。万一 SPI 版なら輸送層だけ
  差し替え、SSD1306 のコマンド層は共通に保つ (下の層分け)。

## 層分け

- **boards/k210/i2c.c** (ボード層): I2C0 マスタ送信ドライバ。
  口は `board_i2c_write(addr, buf, len)` の1つに絞る。
  FPIOA 設定 (IO30/31 へ 126/127)、クロック有効化、
  SCL 100kHz (標準速度) の hcnt / lcnt 設定、FIFO ポーリング
  送信。割り込みは使わない (I2S と同じ流儀)。
  クロック有効化ビットと入力クロック周波数の扱いは
  SDK の sysctl 相当をボード層で解く (実装時に実測で確定)。
- **boards/virt/i2c.c** (ボード層): ダミー。送信バイト数を
  klog に出すだけ (gfx / audio の virt ダミーと同じ流儀)。
  virt のビルドと test.sh はこの上で回る。
- **ssd1306.c** (共通): SSD1306 の初期化シーケンス、
  フレームバッファ (128x64 / 8 = 1024 バイト) の転送、
  消去・反転などの基本操作。I2C への依存は
  board_i2c_write の1関数だけ。
  フレームバッファへの描画 (点・文字) もここに置く。
  フォントは LCD と同じ 5x7 大文字フォントを流用する
  (128px 幅で scale 1 = 21 文字 / 行、8 行)。
- **出口**: 段1ではカーネル内だけ (下記)。ユーザープログラム
  用の syscall は段2で、doc/syscalls.md に先に書いてから足す。

## 段立て

### 段1: ドライバ + カーネル内表示

- boards/k210/i2c.c、boards/virt/i2c.c、ssd1306.c を新設。
- カーネル起動時に OLED を初期化し、「KosabaOS」の1行と
  起動カウンタ等を出す。失敗 (モジュール不在) でも起動は
  続ける: I2C の ACK 不在を検出して klog に1行残すだけにする。
  基板2以外・virt ではダミー経由で無害。
- 検証: virt は klog の oled 行で判定する test.sh シナリオを
  追加 (AH 予定)。実機確認はモジュール到着後 (段3)。

### 段2: ユーザープログラムへの出口

- syscall をデバイスブロック (40〜49) の空きに足す。
  形は実装前に syscalls.md で決める。候補:
  (a) oled_blit: 1024 バイトのフレームバッファを渡して転送
  (b) oled_text: 文字列を渡してカーネル側フォントで描く
  LCD の gfx (43〜47) が (b) 型なので、揃えるなら (b)。
  ただし OLED は全面書き換えが安い (1KB) ので (a) でも困らない。
- デモ oled.elf: 引数の文字列を OLED に出す (ima の小さい版)。

### 段3: 実機確認 (モジュール到着後)

- 基板2へ配線 → SRAM ブートで段1の表示確認 →
  test-k210.py に K27 を追加して定例化。
- ついでに溜まっている K25 (seek 実機) も同じセッションで。

## 割り切り

- I2C は送信のみ・ポーリングのみ。受信 (センサ読み等) は
  別の実需が出たら足す (RTC モジュール等)。
- 速度は 100kHz 固定。全画面転送 1KB ≒ 0.1 秒なので、
  毎秒の時計更新には十分。400kHz 化は必要なら後で。
- OLED の焼き付き対策は LCD のセーバーとは別に考えない
  (段1では常時表示しない: 起動表示のみ。常時表示にする
  段で反転・消灯を検討)。
