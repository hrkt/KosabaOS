# nami — 音声ファイル再生プレーヤーの設計

状態: 設計（2026-11-08、ユーザーが着手と名前を決定）。
コマンド名は **nami**（波＝音の波形。Nish・Ikesu・shirasu の
海の並び）。今回の範囲は **WAV の再生**まで。MP3 は形式の
振り分け口だけ用意し、渡されたら「まだ扱えない」と綺麗に
返して終わる。デコーダ本体は作らない（Ikesu 側の独自
デコーダが別にあり、接続は将来の仕事）。

## なぜ IwaC か

nami は gcc ではなく **IwaC**（自作 C サブセット
コンパイラ）で作る。理由は将来の接続にある: MP3 の
デコーダは Ikesu 側で IwaC によって開発が進んでおり
（独自デコーダ段6）、将来 `play_mp3()` の受け口に
デコーダを差すとき、プレーヤーとデコーダが同一の
ツールチェーン・同一の言語サブセットで揃っている方が
繋ぎ目が小さい。nami はその先行例として、IwaC の
プログラムの作法（段6 の main_kosaba.c が前例）で書く。

## ビルド経路と OS への取り込み

- ソースは `arch/riscv64/nami/` に置く（nami.c、
  wavgen.c、build-nami.sh）
- `nami/build-nami.sh` が IwaC のチェーンを回す:
  `iwac --kosaba --elf nami.c` で ELF オブジェクト
  (.eo) を出し、リンカ **nori** で nami.elf に組む
  （wavgen.elf も同じ）。ツールチェーンの場所は
  環境変数 `IWAC_DIR` で差し替え可能（既定は兄弟
  ディレクトリの `~/workspace/iwac/iwac`、IKESU_DIR
  と同じ流儀）。バイナリが無ければ各 build.sh で作る
- OS 側 (build.sh) は IKESU_EMBED と同じ「素材があれば
  取り込む」方式: nami/nami.elf と nami/wavgen.elf が
  そろっていればステージングして -DNAMI_EMBED で
  埋め込み、無ければ取り込まない。その場合 test.sh の
  シナリオ AC は SKIP になる（シナリオ U の扱いに倣う）

## IwaC サブセットへの適合

nami / wavgen のソースは IwaC の現行 main の範囲で書く。
使うもの: 幅つき整数（int32 / int64）、ファイル
スコープの変数と配列、関数、ポインタと配列の添字、
`#define`、組み込みの `putc` と `syscall3`。
**使わないもの**（サブセットの外、または今回の方針）:

- `switch`（未対応）→ 形式の振り分けは if-else で書く
- 浮動小数点（使わない）→ WAV 再生は整数演算のみ。
  wavgen のサイン波も固定小数点の漸化式で作る
- 文字リテラル（コーパスの作法に合わせ、文字コードを
  数で書く。文字列リテラルは使う）
- 構造体（今回は要らない。fmt の項目は個別の変数で持つ）
- `#include` と libc（宣言は自前。入口は `main(argc,
  argv)` で、戻り値が終了ステータスになる --kosaba の
  約束に従う）

## 使い方と登録

- 起動は `run nami <ファイル>`。埋め込み FS には拡張子なしの
  **"nami"** で登録する（名前解決は完全一致なので、これで
  `run nami` の形がそのまま通る。本体ファイルは nami.elf）
- 引数は既存の argv（argv[1] = ファイルパス）。/sd の
  ファイルも RAM FS のファイルも、open/read の既存 syscall
  経由で同じに扱う（nami 自身を /sd に置いて実行することも
  できる）
- 使う syscall は既存のものだけ: open(4) / read(5) /
  close(6) / audio_open(40) / audio_write(41) /
  audio_close(42)。新 syscall はなし

## 形式の振り分け

拡張子は信用せず、**先頭バイト（マジック）で判別**する。

- `RIFF....WAVE` → WAV として解析する
- `ID3`、または MP3 フレーム同期（0xFF の次に 0xE0 台）→
  MP3 と認識し、未対応として断る
- それ以外 → 「形式が分からない」として断る

振り分けは関数境界として分けておく: `play_wav()` が今回の
実装で、`play_mp3()` は「未対応を出すだけの受け口」。
将来 MP3 を扱うときは、Ikesu 側デコーダの呼び出しを
`play_mp3()` の中身として差し込む（振り分けと表示の
約束は変えない）。

## WAV の対応範囲（v1）

- RIFF/WAVE、fmt チャンク + data チャンク。知らない
  チャンクは読み飛ばす（チャンクは偶数境界にそろい、
  奇数サイズにはパディング 1 バイトが付く約束どおり）
- fmt: **PCM（format 1）・16bit・モノラル/ステレオ**だけ。
  data チャンクの宣言サイズの範囲内だけを再生し、
  後続チャンクを音として読まない
- ストリーミング再生: ファイルをメモリに載せ切らず、
  バッファ（4096 バイト）単位で read → audio_write を
  繰り返す。audio_write の部分受け付けには残りを再送
  して対応する。読みはフレーム境界（blockAlign の倍数）
  に切りそろえる

対象外は綺麗に断る: 8bit / 24bit / 32bit、非 PCM
（float・ADPCM 等）、3 チャンネル以上、fmt が無い・
壊れているファイル。

## サンプルレートの方針

- fmt のレートとチャンネル数でそのまま audio_open する。
  **44100 が本線**
- open が -1 を返したら（K210 のドライバは実レートが
  要求の 1% 以内のときだけ受けるので、48000 は -1 に
  なる）、「このレートは扱えない」と表示して終わる
- **リサンプリングは v1 ではしない**。レート変換が要る
  日が来たら、その時に考える

## 表示と終了ステータス

表示は最小限（人が読める短い行だけ）:

- 再生開始: `nami: <パス>` と、WAV が確定したら
  `nami: 44100 Hz mono, 88200 samples (2 s)` の 1 行
  （秒は整数の割り算）
- 正常終了: `nami: done`

終了ステータス（Nish が `run: exit status N` で出す）:

| status | 意味 | 表示の例 |
| --- | --- | --- |
| 0 | 再生が最後まで済んだ | `nami: done` |
| 1 | ファイルが開けない・読めない・再生中の失敗 | `nami: cannot open <パス>` |
| 2 | 引数が足りない | `usage: nami <file>` |
| 3 | 形式は分かるが v1 の対象外（MP3、非 PCM、16bit 以外、レート非対応） | `nami: mp3 is not supported yet` |
| 4 | 形式が分からない・壊れている | `nami: unknown format` |

再生の途中で失敗したら、開いたオーディオは閉じてから
終わる（close の要約行が dmesg に残る形は崩さない）。

## 検証の物差し

再生後の dmesg の `audio: close rate=<r> channels=<c>
samples=<n> fnv=<16 桁>` が、**再生した WAV の data
チャンクのバイト列**から計算した samples / FNV-1a 64bit
と一致すること（virt・実機共通の強い照合。シナリオ T の
FNV 照合と同じ考え方）。

- virt（シナリオ AC）: ホストで make_test_wav.py が
  テスト WAV（44100Hz・モノラル 16bit・440Hz サイン波・
  振幅 8000・2 秒 = 88200 サンプル）を生成し、
  make_sd_image.py の取り込み口（名前=ホストパス）で
  TEST.WAV として SD イメージに置く。期待値はテスト側が
  そのファイルの data チャンクから計算する
- 実機（シナリオ K22）: カードへ WAV を置く手段として
  wavgen.elf（サイン波 WAV を /sd へ create/write で書く
  小さな生成プログラム。nami と同じく IwaC 製で、
  サイン波は固定小数点の漸化式で作る）を用意する。
  wavgen は自分が書いた PCM の FNV を表示し、nami の
  再生後の close 行と装置の中で突き合わせる（ホスト
  生成のサンプル列と一致する必要はない）
- エラー系もシナリオに入れる: 無いファイル（status 1）、
  WAV でない既存ファイル（status 4）、MP3 を渡す
  （ID3 で始まるファイル、status 3）、引数なし
  （status 2）

音が実際に出るかは、スピーカー未接続のため今回の
検証範囲の外（シリアル側の照合まで）。
