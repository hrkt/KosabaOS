# SD カード書き込み対応の計画（FAT32 write）

状態: 計画（2026-11-07 作成、未着手）。読み取り側の設計は
doc/sd-design.md、全体の段取りは doc/sd-roadmap.md。
ここでは書き込み対応の範囲・段・決め事を固定する。
決め事は段0 としてこの文書に置き、実装は段1 から。

## 背景と実需

- 現状の /sd は FAT32 読み取り専用（8.3 名のみ、遅延マウント、
  新規 syscall なし、create は -1）。読む側の配線は揃っている:
  blkdev の抽象、fat.c（マウント・検索・一覧・読み）、
  trap.c の fd ごとの is_sd 区別、virt 用イメージ生成
  （make_sd_image.py）。
- 実需 1: Ikesu でデコードした WAV を SD に書いて再生する形
  （デコードと再生を分ける実用形の前提）。
- 実需 2（将来）: exec の追い出し（凍結した親を SD へ書く）の
  前提にもなる。

## 段取り

### 段1: 書く土台

- blkdev に write を足す（ramdisk と SD 実機ドライバ sd_hw.c）。
  SD のブロック書き込み（CMD24 系、カードの busy 待ち）を
  ボード層に閉じる。
- fat.c の FAT キャッシュ（現状は読み専用の 1 セクタ）を、
  書き戻しできる形にする。
- 検証環境を先に作る: virt のイメージへ書いた結果をホストで
  マウントして読み、fsck.fat で整合を確かめる段取り
  （make_sd_image.py の延長）。

### 段2: FAT 書き込みの中核

- 空きクラスタの確保（FAT 走査）とチェーンの延長。
- FAT の更新は 2 面とも（片面だけだと PC 側と不整合になる）。
- ディレクトリエントリの作成（8.3 名）と、close 時の
  サイズ・開始クラスタの書き戻し。
- 物差し: virt で「新規作成 → 書き込み → 閉じる → イメージを
  ホストで読んでバイト一致 ＋ fsck クリーン」。

### 段3: 配線

- trap.c の /sd 経路で create / write / unlink を生かす。
  新規 syscall は足さない（既存の口を SD にも通す）。
  Nish からそのまま書けるようになる。test.sh にシナリオ追加。
- SD 上の mkdir は配線の形を見て、この段に含めるか判断する。

### 段4: 実機

- 実カードで往復確認（OS で書く → PC で読む、PC で書く →
  OS で読む）。test-k210.py にシナリオ追加。
- 犠牲にできるカードで試す（普段使いのカードでは試さない）。

## 決め事（推奨として置く、着手時に最終確認）

1. **範囲**: ルート＋既存ディレクトリ内への作成・書き込み・
   削除まで。名前は 8.3 のみで、LFN（長い名前）は対象外
   （読み側と揃える）。
2. **書き込み順序**: データ → FAT → ディレクトリの順に書き、
   サイズは最後（close 時）に確定させる。中断したときの被害を
   「書いていたそのファイル」に寄せるための順序。
3. **FSInfo**: 空きクラスタ数の記録は close 時に更新する
   （PC 側のチェックと喧嘩しないため）。
4. **タイムスタンプ**: ディレクトリ項の日時にはカーネルの
   壁時計（time_read、RTC 由来）を使う。未設定の間は 0
   （1980-01-01 扱い）のままにする。

## 割り切り

- ジャーナルは作らない。書き込み中の電源断では、最悪その
  ファイルが壊れる（FS 全体を守る仕組みは持たない）。
- 同時書き込みは 1 ファイルのみ（現行の exec モデルでは
  ユーザープログラムは 1 本だけなので実害なし）。
- SD からの exec は引き続き対象外（読み側の割り切りを継承）。

## 未決

- 追記（append）と上書きの境目を open の形でどう表すか
  （RAM FS 側の既存の意味づけに合わせるのが第一候補）。
- 大きなカードでの空きクラスタ走査の速度（実測してから、
  必要なら探索開始位置のヒントを持つ）。
