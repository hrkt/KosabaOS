# synth — シンセ音源アプリの設計メモ (段1)

状態: 段1 実装 (2026-11-25、branch `synth-app`)。
コマンド名は **synth**。nami と同じく IwaC の C サブセットで
書き、iwac --kosaba --elf → nori でビルドする
(`arch/riscv64/synth/build-synth.sh`)。OS 側 build.sh は
成果物があるときだけ -DSYNTH_EMBED で取り込み、拡張子なしの
"synth" で登録する (nami と同じ流儀)。

## 使い方

- `run synth` / `run synth fm` — FM デモ曲 (32ステップ×0.25秒=8秒)
- `run synth psg` — PSG で同じデモ曲 (ノイズのハット付き)
- `run synth play fm` / `run synth play psg` — 対話モード
  - 鍵盤: 下段 `z s x d c v g b h n j m ,` と上段
    `q 2 w 3 e r 5 t 6 y 7 u i` が半音ずつ上がる 2 オクターブ
  - `o` / `p` で基準音 (既定 C4) をオクターブ上下、ESC / Ctrl-C で終了
- `run synth midi <path>` — MIDI バイト列ストリームを読んで鳴らす
  (下の SMF プレーヤーの節)。FM はマルチティンバー版で
  `[pool 1-32] [2op|4op] [dbg]` の追加引数あり
  (下のマルチティンバーの節)
- プリセット (FM / PSG 各 16) は `run synth fm <番号>` 等の
  引数、対話モードの `[` / `]` キー、MIDI のプログラム
  チェンジでロードできる (下のプリセットの節)
- 終了時に `synth: samples=<総数> fnv=<16進16桁>` と
  `synth: done` を印字する。virt では dmesg の
  `audio: close ... samples= / fnv=` 行と照合できる (wavgen の流儀)
- 戻り値: 0=正常、1=オーディオを開けない/書き込み失敗、2=引数不正

## 段1 の音源仕様

- 出力: 44100Hz・モノラル 16bit、audio syscall 40〜42 のみ
  (新 syscall なし)。書き込みは 1024 サンプル塊、部分受け付けは再送
- 共通ボイス: 4 ボイス、ラウンドロビン割り当て。簡易 ADSR
  (attack 約2.5ms、decay で sustain 61% へ、gate が切れたら
  release 約25ms)。状態は 1 ボイス 16 ワードで g_vs (下記) に持つ
- FM: 2 オペレータ。搬送波の位相を変調波 (周波数比 3.5) で変調。
  正弦波は 256 点 Q15 テーブル + 線形補間、位相は 1 周=65536 の
  固定小数点。変調の深さは専用エンベロープで減衰する
  (ベル / エレピ寄り)。音程表は MIDI 36〜96 の位相増分を
  ホストで計算し、関数内で代入で埋める (初期化子は使わない)
- PSG: 矩形波 (デューティ 50%)。ノイズは 16bit LFSR を
  1 チャンネルとして同じボイス枠で扱う
- ミキサー: 全ボイスを整数で加算し ±30000 でクリップ

## 割り切り (段1)

- 端末にはキーアップが無いので、対話モードでもキーを押すと
  gate (約0.36秒) 分だけ鳴って自動で release に入る。
  本当のゲート (押している間鳴る) は MIDI 入力待ち
- 現行の audio リングは 8192 フレーム (約186ms) なので、
  対話モードの発音遅延はその分ある。低遅延化は OS 側
  realtime-prep (doc/realtime-audio-design.md) の段2 の仕事で、
  synth 側は現行の口のまま追随する
- 実効レートは K210 で 44010Hz のため音程は約 -0.2% 低い
- ファイルスコープには char 配列だけ置き、表とボイス状態は
  その中へ rd32 / wr32 (バイト合成) で読み書きする
  (nori の配置ずれ対策、doc/nami-design.md)
- main に大きなローカル配列 (正弦波表など) を置くと IwaC の
  フレーム生成が壊れることを実測した (フレーム 1504 バイトで
  プロローグの `addi sp,sp,-N` の符号が反転して +N になり、
  スタック上端の外へ書いて即フォールト。nami の main は
  フレーム 80 バイト)。ローカルはスカラだけに保つこと。
  IwaC 側で直すべき問題として切り分ける

## SMF プレーヤー (smfplay)

Standard MIDI File を再生する別プログラム `smfplay`
(`arch/riscv64/synth/smfplay.c`、synth と同じく IwaC 製、
build-synth.sh が一緒にビルドし、OS 側は素材があるときだけ
拡張子なしの "smfplay" で取り込む)。

- 役割分担: smfplay は**仮想 MIDI デバイス**。SMF を解析し、
  テンポマップに従って実時間に刻みながら (uptime=31 で読み、
  sleep_ms=34 で待つ)、生の MIDI バイト列を送り先へ出す。
  synth は届いたバイト列をそのまま解釈して鳴らす
  (実鍵盤と同じ経路)
- **デルタ先送りをしない理由**: ファイル内のデルタタイムは
  SMF 形式そのものなので解析には使うが、送り先へデルタを
  渡して受け手に数えさせる形は取らない。本物の MIDI の線に
  タイミング情報は無く、バイト列が演奏時刻に届くこと自体が
  実物だからで、先送りすると時計の仕事が synth 側へ移り、
  実経路のジッタも検証できなくなる
- 送り先は `send_event()` の関数境界の向こう。本命は OS 側
  realtime-prep 段4 の L2 入力キュー + 注入 syscall で、
  来たらそこへ差し替える。暫定経路は 2 つ:
  - `run smfplay <file.mid>` — イベントを時刻つきログに
    出す (検証用)
  - `run smfplay <file.mid> file <path>` — 生バイト列を
    その時刻にファイルへ書いていく。終わりに終了マーカー
    として private SysEx `F0 7D 00 F7` を書いて閉じる
    (実キューが来るまでの暫定約束)
- synth 側の受け手は `run synth midi <path> [fm|psg]`:
  ファイルをバイト列ストリームとしてポーリング読み
  (未着分は sleep_ms で少し待って再試行) し、逐次解釈する。
  ノートオン/オフは本物のゲート (オフで release)、
  プログラムチェンジは GM 番号からエンジン内のプリセットを
  引く (下のプリセットの節)、CC 120/123 は全音止め。
  終了マーカーで余韻 11025
  サンプルを描いてから閉じる。同時実行 (smfplay を
  ジョブで流しながら synth が読む) も virt で確認済み
- 対応範囲: format 0 / 1 (全トラックを時刻順にマージ、
  テンポは同一 tick なら小さいトラック番号を優先)、
  division は PPQ のみ (SMPTE は断る)、ランニング
  ステータス、テンポ設定メタ FF 51、トラック終了 FF 2F。
  SysEx と他のメタは読み飛ばす。ベロシティの大きさは
  synth 側で使わない (0=オフの扱いだけ守る)
- 制限: ファイルは丸ごと読みで上限 32768 バイト、
  イベント最大 4096、テンポ最大 256、トラック最大 32
- virt 検証 (2026-11-25): テスト曲 (make_test_mid.py、
  format 0/1 両版、テンポ変更 2 回、約 10.3 秒) で
  log モードのイベント時刻が予定と最大 11ms 差で一致、
  ファイル経由のパイプラインと同時実行ライブ再生の
  両方で synth の samples/FNV が audio close 行と一致

## プリセット (FM / PSG 各 16)

FM と PSG に 16 個ずつプリセット音色を持ち、ロードできる。
General MIDI (GM) の楽器分類を参考に、異なるファミリーから
拾った。定義は synth.c の `fill_presets()` にあり、1 件
20 バイトのバイトパックでファイルスコープの char 配列
(g_pfm / g_pps) に置く。名前 (16 バイト枠) も別表に持つ。
発音時、trig が現在のプリセットの実効パラメータをボイス
ごとの作業領域 (g_vp) へ写し、mix_sample はそれで回る。

エンジン拡張は最小限に絞った: エンベロープの 4 値
(attack / decay / sustain / release) とレベルをボイスごとに
持つこと、FM の変調比と変調の深さ・変調 env の減衰率、
PSG のデューティ可変・ノイズ混合・オクターブシフト。
フィードバックやビブラートは入れていない (必要になったら
プリセット形式の空きバイトで足せる)。op モード
(2op / 4op) は後の節で足し、+18 バイトを使う。

**0 番は段1 の従来音色そのもの** (全パラメータが従来の
固定値と一致)。番号なしで起動した場合のデモの FNV は
従来と変わらない (FM 79b7a119033bb71b / PSG
d8c200d36c6c30cd、virt で再確認済み)。

## マルチティンバー (FM) と DVA

MIDI モードの FM は 8 パートのマルチティンバーにした
(デモ / 対話モードと PSG の MIDI モードは従来通り
単一パート・モノラル)。狙いは音を鳴らすこと自体に加えて、
後の「負荷計測」の節の通り負荷テストの道具にすること。

- パート: MIDI ch 1..8 がそのままパート 1..8。各パートは
  プリセット (プログラムチェンジはそのチャンネルだけに
  効く)、ボリューム (CC7)、パン (CC10) を個別に持つ。
  ch 9 以降は無視する
- 出力はステレオ (audio_open 44100 / 2ch)。パンは線形
  (L ゲイン = (127 - pan) / 128、R ゲイン = pan / 128) で
  ボイスごとに掛け、ミックス後に ±30000 でクリップ
- ボイスプール: 全パート共有で最大 32 ボイス。起動引数
  `run synth midi <path> fm <pool 1-32>` で上限を絞れる
  (負荷スイープ用)。ボイス状態は所属 ch・ノート・位相・
  env 段階・発音順 seq を char 配列にバイトパック
- DVA の割り当て規則 (ノートオン時):
  1. 同じ (ch, note) が鳴っていればそれを再トリガ
  2. 空きボイス
  3. release 中の最も古いボイスを奪う
  4. 全体で最も古いボイスを奪う (steal)
  パートごとの同時発音上限は 8 で、上限に達したパートは
  自パートの最も古いボイスを奪う。ノートオフは
  (ch, note) が一致するボイスだけを release に入れ、
  CC 120/123 はそのチャンネルのボイスだけを止める
- デバッグ: 引数に `dbg` を付けると割り当てのたびに
  `synth: alloc v=<n> ch=<c> note=<n> [steal]` を印字する

パートの初期プリセット (GM 的な既定割り当て):

| パート (ch) | プリセット | 想定 |
| --- | --- | --- |
| 1 | 0 Grand Piano | 主旋律 |
| 2 | 9 Electric Bass | ベース |
| 3 | 10 Strings | 和音 |
| 4 | 1 Electric Piano | 副旋律 |
| 5 | 6 Acoustic Guitar | 伴奏 |
| 6 | 11 Trumpet | ブラス |
| 7 | 12 Flute | 木管 |
| 8 | 15 Synth Pad | パッド |

対象外: ch 10 のドラム (下の将来課題)、PSG の
マルチティンバー、パートごとのエフェクト。

## FM の 4 オペレータ化

負荷ノブ兼音質として、FM に 4op モードを足した。
アルゴリズムは 2 種に絞る (フィードバックは入れない):

- モード 1 (直列スタック): op1 -> op2 -> op3 -> carrier。
  変調比は全 op 共通、深さは内側ほど浅く (1/4、1/2、1) して
  破綻を避ける。変調 env は 2op と共有
- モード 2 (2+2 ペア): 既存の 2op を 2 本混ぜる。2 本目は
  変調の深さ半分、キャリアを僅かにデチューン (+1/256)
  して厚みを出す

プリセットの +18 バイトが op モード (0=2op / 1=スタック /
2=ペア)。4op のプリセットは FM 1 (E.Piano, スタック)、
6 (A.Guitar, スタック)、7 (E.Guitar, ペア)、8 (A.Bass,
スタック)、9 (E.Bass, ペア)、11 (Trumpet, ペア)、
14 (Synth Lead, ペア)。ベル系 (2/3/4/13) は 2op のまま。
**0 番 Grand Piano は従来音色の保存のため 2op のまま**
にしてあり、デモの FNV は不変 (79b7a119033bb71b)。
負荷スイープ用に、MIDI モードでは引数 `2op` / `4op` で
全ボイスの op モードを上書きできる (4op はスタック固定)。

## 負荷計測 (perf_read)

マルチティンバー版 MIDI モードは描画コストを自己計測し、
終了時に `synth: perf ...` の形で印字する:

- 描画チャンク (512 フレーム) の前後で perf_read (33 番、
  0=サイクル / 1=命令数) を読み、チャンクごとのコストを
  積算する。印字は総サイクル、命令数、平均 cycles/frame、
  最悪チャンクのコスト、同時発音数のピーク
- 予算: 512 フレームは 44100 Hz で約 11.6 ms 分。最悪
  チャンクの予算比 (%) = 最悪コスト / (較正した
  cycles/ms × 11.609)。cycles/ms は起動時に uptime と
  perf_read の差分 (100 ms の sleep を挟む) で較正する
- virt の数字の読み方: QEMU の cycle カウンタはホストの
  進み方に引きずられるので、サイクル数と予算比は目安。
  命令数 (ins/frame) は決定的で、構成比較はこちらが正。
  実機 K210 (390 MHz) の予算は 390e6 / 44100 =
  約 8843 cycles/frame で、実機で「間に合ったか」の
  最終判定は audio close 行の under (無音ブロック数)
- ストレス曲: make_test_mid.py の SONG5.MID。ステージ
  ごとに同時発音が 4 -> 8 -> 16 -> 24 -> 32 と増える
  (各 1920 tick = 2 秒、境界 tick 0/1920/3840/5760/7680、
  smfplay の log と突き合わせ可能)。全 8 パート使用、
  ステージ境界でプログラムチェンジ、最終ステージは
  ch 1 に 16 分音符の連打入り

virt 実測 (2026-11-25、SONG5 をファイル先行書式で再生。
イベントが先行して届くため同時発音は上限に張り付き、
負荷は上限側の見積もりになる):

| pool | op | 平均 cycles/frame | ins/frame | 最悪チャンク予算比 | ピーク |
| --- | --- | --- | --- | --- | --- |
| 4 | 既定 | 7,872 | 10,027 | 78% | 4 |
| 8 | 既定 | 14,259 | 17,001 | 193% | 8 |
| 16 | 既定 | 20,680 | 22,834 | 212% | 16 |
| 32 | 既定 | 36,150 | 38,622 | 428% | 32 |
| 32 | 2op 固定 | 30,625 | 33,262 | 353% | 32 |
| 32 | 4op 固定 | 43,677 | 46,704 | 769% | 32 |

読み取れること: ins/frame は pool にほぼ比例して増え、
4op は 2op の約 1.4 倍。K210 の予算 (約 8843
cycles/frame、IPC を 1 と仮定) と比べると、現行の
IwaC 生成コードでは 4 ボイス級が実時間の目安で、
16/32 ボイス全開は実機では間に合わない見込み。
ただしこれは virt の命令数からの推算で、実機の負荷は
未検証 (under と耳の確認は実機セッション待ち)。

## 段立て全体

- **段1 (今回): FM + PSG** — 上記。共通ボイス/ミキサー/ADSR の枠を作る
- **段2: Roland LA 音源風** — 短い PCM アタック (打鍵・撥弦の
  頭だけ) + 減算合成のサステイン部、という LA 合成の骨格。
  アタック素材の持ち方 (埋め込み表か /sd のファイルか) が論点
- **段3: PCM 風** — サンプルそのものをオシレータとして使う
  (ループ再生、ピッチシフトは再サンプリング)。素材は /sd 前提
- **段4: アナログシミュレーション** — 鋸波/パルス + ローパス
  フィルタ + レゾナンス、オシレータのドリフトとデチューンで
  「揺れ」を作る。フィルタは 1 サンプル毎の固定小数点演算が本命
- **その先: ミキサー / エフェクト / MIDI 入力** — リバーブ・
  ディレイと、OS 側 realtime-prep 段4 の MIDI 入力 (DIN/UART)
  に接続して鍵盤で弾く。複数プログラムのミキシングは当面せず、
  音源+ミキサー+エフェクトを synth 1 本に内蔵する形で足りる
- **ch 10 = PCM ドラム (将来課題、未実装)** — GM ドラム
  チャンネルは YAMAHA V50 の PCM リズムへのオマージュとして
  PCM ドラムにしたい (ユーザーの案)。今は実装しない。
  段3 (PCM 風) の素材の持ち方と合流する想定
