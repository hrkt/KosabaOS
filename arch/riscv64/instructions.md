# RISC-V 命令メモ (riscv64)

`start.S` で使った命令と、その周辺（レジスタ、メモリ、
アセンブラへの指示）を集めた早見表。「これ何だっけ」を
なくすためのもの。新しいものを使ったらここに足していく。

書き方の約束:

- `rd` は結果を入れるレジスタ、`rs` は元のレジスタ、`t0` のような
  具体名で書いた場合は実際の使われ方
- 「疑似命令」と書いたものは、本物の命令ではなく、アセンブラが
  本物の命令 (の組) に置き換えてくれる便利な省略形

## 構文の読み方（順番とかっこ）

命令の 1 行は、だいたいこの形をしている:

```
命令  結果の置き場, 材料, 材料
```

### 順番: 原則「結果が最初」

ほとんどの命令は **左に書いたレジスタに、右側の計算結果が入る**。
式に直して読むと迷わない:

```asm
addi s1, s1, 1    ; s1 = s1 + 1        (左の s1 が結果、右が材料)
andi t1, t1, 0x20 ; t1 = t1 & 0x20
lbu  a0, 0(s1)    ; a0 = メモリから読んだ 1 バイト
li   t0, 0x10000000 ; t0 = 0x10000000  (材料は数字そのもの)
```

数字を直接書いた材料は「即値（immediate）」で、その場の値として
使われる。レジスタ名を書けば、そのレジスタの中身が材料になる。

例外は store（書く命令）で、結果を入れるレジスタが存在しない
ので、並びが「書く値, 宛先の住所」になる:

```asm
sb a0, 0(t0)  ; メモリ[t0 + 0] = a0 の下位 1 バイト
              ; a0 が「書く値」、かっこの方が「宛先」
```

### かっこ: `ずらし(基準レジスタ)` は「メモリの住所」

かっこが出てきたらメモリ（やデバイス）への読み書きの合図。
住所は「基準レジスタの中身 + 前の数（ずらし、offset）」で
計算される:

```asm
0(s1)  ; 住所 = s1 の値 + 0  → s1 が指すその場所
5(t0)  ; 住所 = t0 の値 + 5  → ベースから 5 バイト先
```

実例で通して読むと:

```asm
lbu t1, 5(t0)  ; t0 は UART ベース (0x10000000) なので
               ; 住所 0x10000005 = LSR を読んで t1 へ
sb  a0, 0(t0)  ; 住所 0x10000000 = THR へ a0 の 1 文字を書く
```

- ずらしは -2048 〜 +2047 の範囲の符号付き数
- かっこが無い命令はレジスタ同士の計算だけで、メモリには触らない
- 注意: `%pcrel_hi(stack_top)` のようなかっこは別物で、あれは
  メモリの住所ではなく「アドレス計算の上半分をここに埋めて」
  というアセンブラへの指示（各命令の説明を参照）

## レジスタ

### 概要

レジスタは CPU の中にある超高速の小さな変数箱。RISC-V (RV64) には
汎用レジスタが 32 個あり、1 個の幅は 64 ビット (8 バイト)。
ハードウェア名は `x0` 〜 `x31` だが、プログラムでは役割を表す
別名 (ABI 名) で書くのが普通。

| 番号 | 別名 | 役割の目安 | 呼び出された側が中身を守るか |
| --- | --- | --- | --- |
| x0 | zero | 常に 0 (書いても捨てられる) | — |
| x1 | ra | 戻り先の住所 (call が記録する) | 呼び出し側が守る |
| x2 | sp | スタックの先頭 | 守られる (増減はする) |
| x3 | gp | グローバル変数用の基準 (今は未使用) | — |
| x4 | tp | スレッド用の基準 (今は未使用) | — |
| x5〜x7 | t0〜t2 | 一時的な計算用 | 守られない |
| x8 | s0 (fp) | 保存される変数 (フレームポインタ兼用) | 守る |
| x9 | s1 | 保存される変数 | 守る |
| x10〜x17 | a0〜a7 | 引数と戻り値 (戻り値は a0、必要なら a1) | 守られない |
| x18〜x27 | s2〜s11 | 保存される変数 | 守る |
| x28〜x31 | t3〜t6 | 一時的な計算用 | 守られない |

「守る/守られない」は関数の呼び合いでの約束事 (呼び出し規約):

- **t 系 (一時的) と a 系 (引数)** は、呼び出された側が自由に
  壊してよい。呼ぶ側は「戻ってきたら中身は変わっているかも」と
  思って使う
- **s 系 (保存)** は、呼び出された側が使うなら、元の値を
  退避してから使い、戻る前に復元しなければならない。
  呼ぶ側は「呼び出しをまたいでも残っている」と信頼できる

この他に、汎用レジスタとは別枠で PC (今実行している命令の住所)
と CSR (CPU の状態や設定を入れる特殊レジスタ群) がある。
CSR はトラップやページングのステップで登場する。

### KosabaOS が使っている範囲

手書きのアセンブラ (start.S) が直接使うのは 4 個だけ:

| レジスタ | KosabaOS での中身 | 置かれている理由 |
| --- | --- | --- |
| sp | スタックの先頭 (stack_top) | 専用の役割が決まっている |
| t0 | .bss ゼロ埋めの「今の住所」 | 使い捨ての一時用なので t 系 |
| t1 | .bss ゼロ埋めの「終わりの住所」 | 同上 |
| ra | kmain を call した戻り先 | ハードウェア + call/ret の仕組み |

C 言語化する前は s1 (文字列の読み取り位置) や a0 (1 文字) も
手で割り当てていた。今は C 側のレジスタの使い分けはコンパイラが
呼び出し規約どおりに行う。たとえば `uart_getc()` の戻り値は
a0 に入って戻ってくるし、関数をまたいで残したい値は s 系に
置かれる。手書き時代に学んだ約束が、そのままコンパイラの
動きの読み方になっている。

## 値を入れる・計算する

### li — Load Immediate (疑似命令)

レジスタに数をそのまま入れる。

```asm
li a7, 1          ; a7 = 1
li t0, 0x10000000 ; t0 = UART のアドレス
```

値の大きさによって、裏では `addi` だけ、あるいは `lui` + `addi`
などに展開される。「とにかくこの数を入れて」と頼む書き方。

### lui — Load Upper Immediate

即値の上位 20 ビットをレジスタに入れ、下位 12 ビットは 0 にする。
計算: `rd = 即値 << 12`。

```asm
lui t0, 0x10000   ; t0 = 0x10000000
```

逆アセンブル結果に現れる。大きなアドレスを作る土台になる命令。

### auipc — Add Upper Immediate to PC

「今いる場所 (PC)」を基準にアドレスを作る。計算:
`rd = PC + (即値 << 12)`。4KB ページ単位の大ざっぱな移動が役目で、
細かい位置合わせはペアの `addi` が行う。

```asm
auipc sp, %pcrel_hi(stack_top)  ; stack_top のあるページへ
```

`%pcrel_hi(目標)` は「PC から目標までの距離の上位部分」という
アセンブラへの指示。`la` 命令と違い GOT を経由しないので、
裸のカーネルでも動く。

### addi — Add Immediate

レジスタに小さい数を足す。計算: `rd = rs + 即値`。
即値は 12 ビット符号付き (-2048 〜 +2047)。

```asm
addi sp, sp, %pcrel_lo(.Lsp) ; ページ内の細かい位置合わせ
addi s1, s1, 1               ; ポインタを 1 文字分進める
```

`%pcrel_lo(ラベル)` は、直前の `auipc` とペアで使う下位部分の指示。

### andi — And Immediate

レジスタと即値の AND (ビットごとの AND) を取る。計算:
`rd = rs & 即値`。「特定のビットだけを取り出す」ための命令。

```asm
andi t1, t1, 0x20  ; LSR の bit5 だけを残し、他を 0 にする
```

## メモリとデバイスを読む・書く

メモリも MMIO のデバイスも、住所を指定して読み書きする点は同じ。

### lbu — Load Byte Unsigned

住所から 1 バイト読み、上位を 0 で埋めてレジスタに入れる。

```asm
lbu a0, 0(s1)   ; 文字列の今の位置から 1 文字読む
lbu t1, 5(t0)   ; UART の LSR (+5) を読む
```

`0(s1)` は「s1 の住所 + 0」の意味。括弧内が基準のレジスタ、
前の数がずれ (オフセット)。

### sb — Store Byte

レジスタの下位 1 バイトを住所へ書く。

```asm
sb a0, 0(t0)    ; UART の THR (+0) へ 1 文字置く = 送信される
sb t1, 3(t0)    ; UART の LCR (+3) に設定を書く
```

### ld / sd — Load / Store Doubleword

8 バイト単位の読み (ld) と書き (sd)。レジスタ 1 個分
(64 ビット) まるごとの大きさで、trap.S がレジスタの
退避 (sd) と復元 (ld) に使う。

```asm
sd ra, 0(sp)    ; ra をスタックに退避する
ld ra, 0(sp)    ; 復元する
```

## 分岐と呼び出し

### beq — Branch if Equal

2 つのレジスタの中身が等しければラベルへ飛ぶ。
等しくなければ次の命令に進む。逆向きの `bne` (等しくなければ飛ぶ)
もある。

```asm
beq t0, t1, 2f  ; ゼロ埋めの住所が終わりに届いたらループを抜ける
```

### beqz — Branch if Equal to Zero (疑似命令)

レジスタが 0 ならラベルへ飛ぶ。本体は `beq rs, zero, ラベル`。

```asm
beqz a0, 2f     ; 文字が 0 (文字列の終わり) なら前方ラベル 2 へ
beqz t1, 1b     ; bit5 が 0 (送信窓口がまだ) なら後方ラベル 1 へ
```

数字ラベルの後ろの `f` は前方 (forward)、`b` は後方 (backward)。

### j — Jump (疑似命令)

無条件にラベルへ飛ぶ。本体は `jal zero, ラベル`
(戻り先を捨てる jal)。

```asm
j 1b   ; ループの先頭へ戻る
```

### call — 関数呼び出し (疑似命令)

ラベルへ飛び、戻り先の住所を `ra` に記録する。裏では
`auipc` + `jalr` の 2 命令。相手は `ret` で戻る。

```asm
call uart_putc  ; a0 の 1 文字を出す部品を呼ぶ
```

### ret — Return (疑似命令)

`ra` に記録された戻り先へ飛ぶ。本体は `jalr zero, ra, 0`。

## その他

### wfi — Wait For Interrupt

割り込みが来るまで CPU を眠らせる。仕事が無いときの「駐車」に使う。
現在の置き場は start.S の最後で、C の kmain から万一戻ってきた
ときに暴走しないための受け皿 (kmain は戻らない想定なので保険)。
割り込みを扱うステップでは、本来の「待ち方」として活躍する。

## アセンブラへの指示 (. で始まる行)

CPU の命令ではなく、「アセンブラ (翻訳プログラム) へのお願い」。
機械語には直接ならないが、配置や中身の作り方を決める。

### .align n — 住所を揃える

次のデータの開始住所を 2^n バイトの倍数に揃える
(RISC-V の GAS では n バイトではなく 2 の n 乗)。
不足分は空き (パディング) になる。

```asm
.align 4   ; 次を 16 バイト (2^4) の倍数の住所から始める
```

start.S では stack の直前にあり、スタックの住所が 16 で
割り切れることを保証している (理由は下の「メモリの話」)。
実物でも stack = 0x802000a0 のように末尾が 0 になっている。

### .space n — 空っぽの領域を確保する

n バイト分の場所だけを取る (中身は .bss の中ならゼロ)。

```asm
.space 4096   ; スタック用に 4KB
```

### .string — 文字列を置く

文字列を置き、末尾に自動で 0 を付ける。この 0 が
「文字列の終わり」の合図になる。

```asm
.string "hello from KosabaOS (S-mode)\n"
```

### .section — 「ここからは ○○ の領域」と宣言する

`.section .text` (命令)、`.section .rodata` (読み取り専用データ)、
`.section .bss` (初期値ゼロの領域) のように、置く場所の種類を
切り替える。最終的な住所は kernel.ld が決める。

### .globl — 名前を外から見えるようにする

`.globl _start` のように、ラベルを他のファイルからも
参照できる印にする。リンカが入口として見つけるために必要。

## メモリの話

### 住所とメモリマップ

住所 (アドレス) はメモリやデバイスに付けられた通し番号で、
1 つずつが 1 バイトの置き場所に対応する。QEMU virt での現状:

| 住所 | 正体 |
| --- | --- |
| 0x10000000 | UART (デバイス。RAM ではない) |
| 0x80000000 〜 0x88000000 | RAM (build.sh で 128MB と指定している分) |
| 0x80000000 〜 0x80200000 | OpenSBI が使っている先頭 2MB |
| 0x80200000 〜 | KosabaOS 自身 (.text → .rodata → .bss の順) |

RAM の住所に書けば値が残り、デバイス (MMIO) の住所に書けば
「命令」になる、という違いが UART ドライバの要点だった。

### セクションがメモリに届くまで

1. アセンブラが start.S を kernel.elf に翻訳する (住所は
   kernel.ld の指定どおり)
2. objcopy が kernel.bin (中身だけのバイナリ) を切り出す
3. QEMU がそれを 0x80200000 に置き、OpenSBI が実行を渡す

.text と .rodata はファイルの中に実体がある。.bss は
「ゼロで埋まった領域」という約束だけが記録され、ファイルに
実体は入らない。今は「電源投入直後の RAM はゼロ」という
環境に甘えて動いているが、本来は起動時にカーネル自身が
.bss をゼロで埋めるのが正道 (将来の課題)。

### スタック

関数呼び出しや一時データの置き場。取り決めがいくつかある:

- スタックは**下向きに伸びる**。使い始める住所は確保した領域の
  末尾 (stack_top) で、使うたびに sp は小さい方へ動く
- start.S は .bss の中に 4KB 確保しているだけの仮のスタック
- **sp は常に 16 の倍数**でなければならない (RISC-V の約束事)。
  .align 4 はこのための指定

### 読み書きの大きさ (バイト数)

命令の後ろの文字が大きさを表す: b = 1、h = 2、w = 4、d = 8 バイト。
読み (load) と書き (store) の両方にある。

| 読み | 書き | 大きさ |
| --- | --- | --- |
| lb / lbu | sb | 1 バイト |
| lh / lhu | sh | 2 バイト |
| lw / lwu | sw | 4 バイト |
| ld | sd | 8 バイト |

読み書きで主に使うのは 1 バイトの lb/sb 系で、他に trap.S の
レジスタ退避・復元で 8 バイトの ld/sd を使う。読み側に「u」が付く
ものと付かないもので符号の扱いが違い、たとえば `lb` は
読んだバイトを符号付きと見て上位を埋めるが、`lbu` は常に
0 で埋める。文字やデバイスの状態を読むときは `lbu` が安全。

### アライメント (住所の揃い)

「住所が大きさで割り切れる」状態を揃っているという。
例: 4 バイト読み (lw) は住所が 4 の倍数のとき揃っている。
揃っていない住所への読み書きは、RISC-V では例外 (エラーで
OS に飛ばされる) になることがある決まり。`.align` や
リンカスクリプトの配置指定は、これを防ぐためにある。

### ecall — Environment Call

下の階層 (S モードからなら OpenSBI) を呼ぶ命令。約束は
「a7 = 頼む機能の番号、a0 などに引数、結果は a0 に返る」。
カーネル初期の版は文字出力に使っていたが、今の用途は
タイマの予約 (sbi_set_timer を OpenSBI に頼む) だけ。
将来、ユーザープログラムから OS を呼ぶ「システムコール」でも
同じ命令が (逆向きに) 登場する。

## CSR とトラップまわりの命令

CSR は汎用レジスタとは別枠の、CPU の状態・設定レジスタ群
(stvec、scause、sepc、stval、sie、sstatus、time など)。
読み書きには専用命令が要る。近年の binutils では CSR 命令は
Zicsr 拡張に分類されるので、ビルド時は `-march=rv64i_zicsr` と
指定している (build.sh 参照)。

### csrr — CSR Read (疑似命令)

CSR の値を汎用レジスタに読む。

```asm
csrr a5, scause   ; 例外・割り込みの原因を読む
```

### csrw — CSR Write (疑似命令)

汎用レジスタの値を CSR に書く。

```asm
csrw stvec, a5    ; トラップの飛び先を登録する
```

### csrs — CSR Set Bits (疑似命令)

CSR の指定ビットだけを 1 にする (他のビットはそのまま)。

```asm
csrs sie, a5      ; 割り込み許可ビットを立てる、など
```

逆に指定ビットだけ 0 にする `csrc` もある。

### sret — Supervisor Return

トラップから元の処理に戻る命令。飛び先は sepc の住所で、
割り込み許可などの状態もトラップ前の状態に戻る。
trap.S の最後で、退避したレジスタを全部復元してから使う。
