# RISC-V 命令メモ (riscv64)

`start.S` で使った命令だけを集めた早見表。「これ何だっけ」を
なくすためのもの。新しい命令を使ったらここに足していく。

書き方の約束:

- `rd` は結果を入れるレジスタ、`rs` は元のレジスタ、`t0` のような
  具体名で書いた場合は実際の使われ方
- 「疑似命令」と書いたものは、本物の命令ではなく、アセンブラが
  本物の命令 (の組) に置き換えてくれる便利な省略形

## 値を入れる・計算する

### li — Load Immediate (疑似命令)

レジスタに数をそのまま入れる。

```asm
li a7, 1          ; a7 = 1
li t0, 0x10000000 ; t0 = UART のアドレス
```

値の大きさによって、裏では `addi` だけ、あるいは `lui` + `addi`
などに展開される。「とにかくこの数を入れて」と頼む書き方。

### lui — Load Upper Immediate

即値の上位 20 ビットをレジスタに入れ、下位 12 ビットは 0 にする。
計算: `rd = 即値 << 12`。

```asm
lui t0, 0x10000   ; t0 = 0x10000000
```

逆アセンブル結果に現れる。大きなアドレスを作る土台になる命令。

### auipc — Add Upper Immediate to PC

「今いる場所 (PC)」を基準にアドレスを作る。計算:
`rd = PC + (即値 << 12)`。4KB ページ単位の大ざっぱな移動が役目で、
細かい位置合わせはペアの `addi` が行う。

```asm
auipc sp, %pcrel_hi(stack_top)  ; stack_top のあるページへ
```

`%pcrel_hi(目標)` は「PC から目標までの距離の上位部分」という
アセンブラへの指示。`la` 命令と違い GOT を経由しないので、
裸のカーネルでも動く。

### addi — Add Immediate

レジスタに小さい数を足す。計算: `rd = rs + 即値`。
即値は 12 ビット符号付き (-2048 〜 +2047)。

```asm
addi sp, sp, %pcrel_lo(.Lsp) ; ページ内の細かい位置合わせ
addi s1, s1, 1               ; ポインタを 1 文字分進める
```

`%pcrel_lo(ラベル)` は、直前の `auipc` とペアで使う下位部分の指示。

### andi — And Immediate

レジスタと即値の AND (ビットごとの AND) を取る。計算:
`rd = rs & 即値`。「特定のビットだけを取り出す」ための命令。

```asm
andi t1, t1, 0x20  ; LSR の bit5 だけを残し、他を 0 にする
```

## メモリとデバイスを読む・書く

メモリも MMIO のデバイスも、住所を指定して読み書きする点は同じ。

### lbu — Load Byte Unsigned

住所から 1 バイト読み、上位を 0 で埋めてレジスタに入れる。

```asm
lbu a0, 0(s1)   ; 文字列の今の位置から 1 文字読む
lbu t1, 5(t0)   ; UART の LSR (+5) を読む
```

`0(s1)` は「s1 の住所 + 0」の意味。括弧内が基準のレジスタ、
前の数がずれ (オフセット)。

### sb — Store Byte

レジスタの下位 1 バイトを住所へ書く。

```asm
sb a0, 0(t0)    ; UART の THR (+0) へ 1 文字置く = 送信される
sb t1, 3(t0)    ; UART の LCR (+3) に設定を書く
```

## 分岐と呼び出し

### beqz — Branch if Equal to Zero (疑似命令)

レジスタが 0 ならラベルへ飛ぶ。本体は `beq rs, zero, ラベル`。

```asm
beqz a0, 2f     ; 文字が 0 (文字列の終わり) なら前方ラベル 2 へ
beqz t1, 1b     ; bit5 が 0 (送信窓口がまだ) なら後方ラベル 1 へ
```

数字ラベルの後ろの `f` は前方 (forward)、`b` は後方 (backward)。

### j — Jump (疑似命令)

無条件にラベルへ飛ぶ。本体は `jal zero, ラベル`
(戻り先を捨てる jal)。

```asm
j 1b   ; ループの先頭へ戻る
```

### call — 関数呼び出し (疑似命令)

ラベルへ飛び、戻り先の住所を `ra` に記録する。裏では
`auipc` + `jalr` の 2 命令。相手は `ret` で戻る。

```asm
call uart_putc  ; a0 の 1 文字を出す部品を呼ぶ
```

### ret — Return (疑似命令)

`ra` に記録された戻り先へ飛ぶ。本体は `jalr zero, ra, 0`。

## その他

### wfi — Wait For Interrupt

割り込みが来るまで CPU を眠らせる。仕事が無いときの「駐車」に使う。

```asm
2:  wfi   ; 眠る
    j 2b  ; 目覚めてもまた眠る
```

## アセンブラへの指示 (. で始まる行)

CPU の命令ではなく、「アセンブラ (翻訳プログラム) へのお願い」。
機械語には直接ならないが、配置や中身の作り方を決める。

### .align n — 住所を揃える

次のデータの開始住所を 2^n バイトの倍数に揃える
(RISC-V の GAS では n バイトではなく 2 の n 乗)。
不足分は空き (パディング) になる。

```asm
.align 4   ; 次を 16 バイト (2^4) の倍数の住所から始める
```

start.S では stack の直前にあり、スタックの住所が 16 で
割り切れることを保証している (理由は下の「メモリの話」)。
実物でも stack = 0x802000a0 のように末尾が 0 になっている。

### .space n — 空っぽの領域を確保する

n バイト分の場所だけを取る (中身は .bss の中ならゼロ)。

```asm
.space 4096   ; スタック用に 4KB
```

### .string — 文字列を置く

文字列を置き、末尾に自動で 0 を付ける。この 0 が
「文字列の終わり」の合図になる。

```asm
.string "hello from KosabaOS (S-mode)\n"
```

### .section — 「ここからは ○○ の領域」と宣言する

`.section .text` (命令)、`.section .rodata` (読み取り専用データ)、
`.section .bss` (初期値ゼロの領域) のように、置く場所の種類を
切り替える。最終的な住所は kernel.ld が決める。

### .globl — 名前を外から見えるようにする

`.globl _start` のように、ラベルを他のファイルからも
参照できる印にする。リンカが入口として見つけるために必要。

## メモリの話

### 住所とメモリマップ

住所 (アドレス) はメモリやデバイスに付けられた通し番号で、
1 つずつが 1 バイトの置き場所に対応する。QEMU virt での現状:

| 住所 | 正体 |
| --- | --- |
| 0x10000000 | UART (デバイス。RAM ではない) |
| 0x80000000 〜 0x88000000 | RAM (build.sh で 128MB と指定している分) |
| 0x80000000 〜 0x80200000 | OpenSBI が使っている先頭 2MB |
| 0x80200000 〜 | KosabaOS 自身 (.text → .rodata → .bss の順) |

RAM の住所に書けば値が残り、デバイス (MMIO) の住所に書けば
「命令」になる、という違いが UART ドライバの要点だった。

### セクションがメモリに届くまで

1. アセンブラが start.S を kernel.elf に翻訳する (住所は
   kernel.ld の指定どおり)
2. objcopy が kernel.bin (中身だけのバイナリ) を切り出す
3. QEMU がそれを 0x80200000 に置き、OpenSBI が実行を渡す

.text と .rodata はファイルの中に実体がある。.bss は
「ゼロで埋まった領域」という約束だけが記録され、ファイルに
実体は入らない。今は「電源投入直後の RAM はゼロ」という
環境に甘えて動いているが、本来は起動時にカーネル自身が
.bss をゼロで埋めるのが正道 (将来の課題)。

### スタック

関数呼び出しや一時データの置き場。取り決めがいくつかある:

- スタックは**下向きに伸びる**。使い始める住所は確保した領域の
  末尾 (stack_top) で、使うたびに sp は小さい方へ動く
- start.S は .bss の中に 4KB 確保しているだけの仮のスタック
- **sp は常に 16 の倍数**でなければならない (RISC-V の約束事)。
  .align 4 はこのための指定

### 読み書きの大きさ (バイト数)

命令の後ろの文字が大きさを表す: b = 1、h = 2、w = 4、d = 8 バイト。
読み (load) と書き (store) の両方にある。

| 読み | 書き | 大きさ |
| --- | --- | --- |
| lb / lbu | sb | 1 バイト |
| lh / lhu | sh | 2 バイト |
| lw / lwu | sw | 4 バイト |
| ld | sd | 8 バイト |

今使っているのは 1 バイトの lb 系だけ。読み側に「u」が付く
ものと付かないもので符号の扱いが違い、たとえば `lb` は
読んだバイトを符号付きと見て上位を埋めるが、`lbu` は常に
0 で埋める。文字やデバイスの状態を読むときは `lbu` が安全。

### アライメント (住所の揃い)

「住所が大きさで割り切れる」状態を揃っているという。
例: 4 バイト読み (lw) は住所が 4 の倍数のとき揃っている。
揃っていない住所への読み書きは、RISC-V では例外 (エラーで
OS に飛ばされる) になることがある決まり。`.align` や
リンカスクリプトの配置指定は、これを防ぐためにある。

### ecall — Environment Call (今は使っていない)

下の階層 (S モードからなら OpenSBI) を呼ぶ命令。以前の版は
`a7 = 1` で SBI の「1 文字出して」を呼んでいた。UART ドライバを
自前で持ったので不要になり、現在のカーネルには含まれていない。
将来、ユーザープログラムから OS を呼ぶ「システムコール」でも
同じ命令が (逆向きに) 登場する。
